## 1. Field mapping (first check)
Projection: `buildBrigadeTemporalRows` (`src/scenario/brigade_temporal_emit.ts`), called post-turn from `scenario_runner.ts` after `runTurn` and the headless post-turn actions.
| Retained field | Source | Predicate (`isCommittedInTransitTo`, `sector_offensive_launch_helpers.ts`) |
|---|---|---|
| `mv_state` | `state.military.brigade_movement_state[id].status ?? null` | `movement?.status === 'in_transit'` — **same field, no fallback** |
| `mv_destinations` | `brigade_movement_state[id].destination_sids` (sorted) **if non-empty, else** `brigade_movement_orders[id].destination_sids` (sorted) | `movement.destination_sids ?? []` only — **no order fallback** |
So `mv_destinations` alone cannot distinguish a movement-state destination from an order destination. A derived order target is not `destination_sids` of the state. Consequences: (a) rows with `mv_state: null` and a destination (e.g. the 112th / 4th Guards post-turn 176) show an **order** destination and do not satisfy the predicate; (b) for rows with `mv_state: 'in_transit'` (post-turn 177–179) the destination is the state's own list **if** that list is non-empty. Every `in_transit` writer found sets a non-empty list: `osid_column_movement.ts:640` `[destOsid]`; `brigade_movement.ts:186` `[holdSid]`, `:254` `current.destination_sids` (copied from a `packing` state that carries `[holdSid]`); rewrites keep it (`{...ms, turns_remaining}`, `{...current, …}`). So the mapping matches for these rows under the writer invariant "an `in_transit` state always has non-empty `destination_sids`" (source inference). Residual gap: an `in_transit` state with an empty list would show the order's destination; no such writer exists in the production sources scanned.
Measured rows (post-turn, `loop_index = turn − 1`, from 082/083): 112th and 4th Guards at turns 177, 178, 179: `mv_state in_transit`, `mv_destinations ['op:bosansko_grahovo:bosansko_grahovo_2']`.
