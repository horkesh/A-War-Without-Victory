# Napkin Runbook Index

Use this as a routing page. Open only the topic needed for the current task. Detailed rules retain their original dates and wording in the linked topic files.

## Universal boundaries

1. **Continue authorized work.** Resolve routine reversible choices from canon and evidence. Stop only for a real authority, safety, acceptance-criterion, or costly-scope decision. See [user directives](napkin/entry_detail.md#user-directives).
2. **Protect canon and control.** Do not edit FORAWWV automatically; preserve panel authority, initial OSIDs, deterministic state, save compatibility, and the packaging pause. See [engine runtime](napkin/engine_runtime.md) and [release process](napkin/release_process.md).
3. **Prove the real claim.** A green proxy, wrapper exit, unchanged diff, or source-string check does not prove runtime behavior, historicity, or visual layout. See [QA gates](napkin/qa_gates.md).
4. **Preserve evidence provenance.** Name actors and sources at the claim boundary; retain run IDs, hashes, editions, command exits, and failed gates. See [evidence and diagnostics](napkin/entry_detail.md).
5. **Use the authoritative horizon.** Territory-moving and calibration-affecting behavior retains its required 188-week, full-suite, anchor, and provenance checks. See [release process](napkin/release_process.md) and [QA gates](napkin/qa_gates.md).

## High-frequency hazards

- Count a field's distribution and trace its key before making it a gate.
- Verify both success and failure selectors, tool availability, and the target artifact's own hash.
- A guard must exercise the intended path and fail under a positive control; differential guards prove change, not truth.
- A lookup can establish absence only if it could have found the target.
- Validate rendered UI in the real route and viewport; source text cannot establish visibility or layout.
- Never use destructive Git restoration in a worktree owned by another session.
- Keep CI tests independent of local evidence roots; include fixtures or generate them deterministically.
- Treat missing reported data as unreported, not zero or favorable.
- Desktop mutations are serialize–autosave–broadcast transactions.
- Never junction `node_modules` into a disposable worktree; removal can destroy the target.
