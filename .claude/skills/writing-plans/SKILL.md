# Writing Plans

Create a plan that another qualified engineer can execute without rediscovering authority or scope.

Include:

- intended outcome and explicit non-goals
- exact files or surfaces owned by each task
- governing sources and dependencies
- implementation sequence where dependencies require it
- change-specific checks with pass criteria and evidence paths
- authority boundaries, expensive-run question/cost/stopping rule, and completion conditions
- documentation, review, integration, and activation ownership

Use steps large enough to represent meaningful deliverables. Include code snippets only when they clarify a non-obvious contract; do not require complete implementation code, artificial two-minute steps, or a commit after every action.

A plan-only request produces the plan for review and stops. Do not force an execution-choice question. If implementation is already authorized, continue under the applicable execution workflow.
