# Napkin

Treat a repository napkin as a routing index, not a session log. Curate it only for verified recurring knowledge, explicit maintenance, or stale/duplicated routing. Put detailed examples and changing status in the repository's existing topic or authority files. Preserve dates, sources, directives, and meaning when relocating material. Reading an index does not itself authorize editing it.

## AWWV project source

In an AWWV checkout, read `.claude/skills/napkin/SKILL.md` there as the maintained project workflow, plus repository `AGENTS.md` and relevant Codex runtime instructions. The AWWV index and topics remain under `.claude/napkin.md` and `.claude/napkin/` in that checkout; do not hardcode a user-home copy.

Outside AWWV, use the generic rule above only when the current repository defines a napkin/runbook location. Do not create AWWV paths or fixed quotas in another project.
