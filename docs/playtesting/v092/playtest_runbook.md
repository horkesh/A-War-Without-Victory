# v0.9.2 Playtest Runbook

## Pre-Launch Checklist

- [ ] Stable build link exists.
- [ ] Tester quickstart is posted beside the build link.
- [ ] Feedback form is live and tested once by the operator.
- [ ] Support channel exists with a pinned start-here message.
- [ ] GitHub Issues or Discussions are enabled for deeper bug reports.
- [ ] Privacy note is posted: what feedback is collected, where it is stored, and whether quotes may be anonymized.
- [ ] Code of conduct is posted.
- [ ] Known rough edges are listed honestly from `known_issues_template.md`.
- [ ] Triage board is created from `triage_board.md`.
- [ ] Weekly digest shell is copied from `weekly_digest_template.md`.
- [ ] First-run instructions cover install, start scenario, advance turn, save, and where logs live.

## Pinned Start-Here Message

Welcome to the AWWV v0.9.2 playtest.

Please start with one 40-week scenario unless you already know you want the full campaign. After the run, submit the feedback form while the session is fresh. Bugs can go in `[issue link]`; broader impressions can go in this channel.

Useful links:

- Build: `[build link]`
- Tester quickstart: `[tester_quickstart.md link]`
- Feedback form: `[form link]`
- Known issues: `[known issues link]`
- Bug reports: `[GitHub issues link]`

What we most need: places where the sim felt confusing, ahistorical, unfair, too opaque, or strangely compelling.

## Tester Workflow

1. Download and launch the build.
2. Start the 40-week default scenario.
3. Play naturally; do not optimize for a perfect result.
4. Keep brief notes on confusing UI, surprising outcomes, and AI behavior.
5. Submit the form after the run.
6. File crash/save/load bugs separately with screenshots or logs where possible.

## Operator Cadence

| Day | Action |
|---|---|
| Day -2 | Dry-run install + first-turn flow on the posted build |
| Day -1 | Create form, support channel, known-issues post |
| Day 0 | Post strategy-gamer recruitment message |
| Day 2 | Triage first wave, answer install questions, patch critical blockers if needed |
| Day 7 | Publish digest 1; begin historian/direct outreach |
| Day 14 | Publish digest 2; decide whether to widen to programming/sim communities |
| Day 28-42 | Close first window; write consolidated playtest findings |

## Triage Rules

- Keep crash/save/load issues separate from subjective feedback.
- Do not debate sensitive-history feedback in public threads; acknowledge, capture, and review in canon context.
- Treat "I was confused" as product signal, not player failure.
- Preserve positive signals too; do not only collect defects.
- Do not promise immediate fixes in recruitment spaces.

## Minimum Closure Criteria

The v0.9.2 recruitment package is complete when:

- Recruitment copy exists.
- Feedback form schema exists.
- Operator runbook exists.
- The roadmap points to this package.
- The first real outreach wave can be launched without asking the repo for more assets.

The playtest cycle itself closes later, after operator outreach and tester responses.
