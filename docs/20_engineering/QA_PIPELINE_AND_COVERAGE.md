# QA Pipeline and Coverage Guidelines

**Date:** 2026-03-09  
**Purpose:** Document the unified Quality Assurance pipeline and code coverage metrics introduced in Phase 1 of the Remediation & Refactor Execution Plan.

## 1. Unified QA Script: `npm run qa:all`

The project now provides a single, unified test script to assert total system health across engine logic, UI correctness, and scenario baselines. This should be run before any major commit or PR.

Command: `npm run qa:all`

This command streams the following steps sequentially:
1. **Typechecks:** `npx tsc --noEmit` ensures the TypeScript compiler finds no errors across the core engine and UI.
2. **Fast Node Tests (with Coverage):** `npm run test:coverage` runs the entire `node:test` suite (`tests/*.ts` excluding UI) using Node's native runner. It executes with `--experimental-test-coverage` to output V8 coverage summaries to the console.
3. **Vitest UI Tests (with Coverage):** `npm run test:vitest -- --coverage` runs the JSDOM-dependent tests (e.g. Warroom smoke tests, Map layer builders) using `@vitest/coverage-v8`.
4. **Desktop Map Build:** `npm run desktop:map:build` ensures the React + MapLibre Map UI compiles and bundles cleanly via Vite without chunking or dependency errors.
5. **Scenario Baseline Regression:** `npm run test:baselines` executes `noop_4w`, `baseline_ops_4w`, and the complete `apr1992_definitive_52w` scenarios, asserting that every artifact hash matches the golden committed baseline in `manifest.json`.

## 2. Coverage Targets and Measurement

We now measure coverage across both our testing frameworks.

### Node Core Engine Coverage
- Executed via: `node --experimental-test-coverage tools/test/run_node_tests.mjs`
- Captures test execution paths for the purely deterministic simulation engine logic (`src/sim`, `src/state`, `src/scenario`).

### Vitest UI Coverage
- Executed via: `vitest run --coverage` (requires `@vitest/coverage-v8`)
- Captures coverage for `src/ui/map` and `src/ui/warroom` using the `jsdom` environment.

*Note: While hard enforcement thresholds (e.g. 80% line coverage) are not yet locked in the CI pipeline, developers are expected to review the coverage summaries generated by `qa:all` and ensure new feature work includes corresponding test files.*

## 3. Scenario Baseline Updates

The baseline runner now includes a full 52-week war-phase scenario (`apr1992_52w`). This guarantees that changes to early-war emergence, combat causality, and late-game exhaustion are caught.

When modifying core simulation behavior (e.g. combat modifiers, AI targeting, supply thresholds), you **must** update the golden baselines. 

To update the baseline manifest:
```powershell
# Windows
$env:UPDATE_BASELINES="1"; npm run test:baselines

# Mac/Linux
UPDATE_BASELINES=1 npm run test:baselines
```

**Guardrail:** Never run baseline updates blindly. Only update the baselines when the new behavior is explicitly intended and authorized by the Game Designer or Orchestrator (documented in the `PROJECT_LEDGER`).
