## 2026-11-17 — The in-sim peace phase is retired; schema v41 deletes the peace-only bookkeeping

Since v40 (#773) no scenario can start in peace: every game starts at war, turn 0. The in-sim peace phase was unreachable dead code. This change removes it before the engine freeze.

**Engine removed.**
- `src/state/turn_pipeline.ts` (`runOneTurn`, which threw on war), `src/state/turn_phases.ts` (eight no-op phase handlers) and `src/state/phase_gates.ts`. `strictCompare` now comes from `src/state/validateGameState.ts` (its canonical home; `brigade_temporal_emit.ts` and one test re-pointed).
- The scenario runner's `if (state.meta.phase === 'peace')` branch and its `runOneTurn` import; the dead `early_war_note` (read `war_opposing_edges_streak`); the always-written `war_force_transition_after_turns = 52` and the `war_entrenchment_init_turns` / `war_force_transition_after_turns` scenario fields (no data file used them).
- The non-war reset of `war_front_edges_osid` in `src/sim/turn_pipeline.ts`; the non-war branch of `resolveAggressionForPhase` (always late-war aggression now; week tapering still shapes early war); the uncalled `isEarlyWarAllowed` in `early_war_phases.ts`; the always-passing referendum guard in `run_early_war_browser.ts`.
- `ensureRbihHrhbState` no longer reads `phase0_relationships`; `mapPhase0RelationshipToAlliance` is gone.
- `PhaseName` is `'war'` only. The validator's known phases are `['war']`: a state with `meta.phase: 'peace'` now fails validation (no migration step converts one; none can be produced since v40).

**UI removed.** `PeaceStatusPanel` and its App mount; `derivePeacePhaseData` and the `peace*` fields on `LoadedGameState`; the Phase 0 layouts of FactionOverviewPanel, ReportsModal (pre-war municipality intelligence) and MagazineModal; NewspaperModal's Phase 0 content and the unused September 1991 `startBrief`; `headline_templates.ts` (peace-only); the NewsTicker peace branch; the WarPlanningMap Phase 0 INVEST layer and the deprecated `InvestmentPanel`; the peace-only DeclarationEventModal displays and the unused `checkWarTransition` / `findCriticalEvent` / `showWarBeginsModal` exports (and their import in ClickableRegionManager); the `wrapped.phase.peace` slide label branch; `useIPC`'s dead `phase0Directives` payload; the `?? 'peace'` defaults (now `'war'`). Kept: the war-start intro overlay, `PHASE0_TICKER_EVENTS`, and the `Phase0Event` type (war milestone modals use it).

**War-start intro unchanged.** `shouldMarkPeaceWarTransitionSeenOnLoad(previous, next)` returned `previous?.phase !== 'peace'` for a war load. No previous state can be in peace, so it always returned true. It is now `shouldMarkPeaceWarTransitionSeenOnLoad(next)` = `next.phase === 'war'`. A load marks the intro seen; a fresh April 1992 start re-arms it in App.tsx exactly as before.

**Schema v41.** `CURRENT_SCHEMA_VERSION` 40 → 41. Migration v41 deletes `meta.referendum_held`, `referendum_turn`, `referendum_eligible_turn`, `referendum_deadline_turn`, `peace_scheduled_referendum_turn`, `peace_scheduled_war_start_turn`, `war_opposing_edges_streak`, `war_force_transition_after_turns`, `war_entrenchment_init_turns`, `peace_end_turn`, `war_start_lifecycle_phase_turn`, `escalation_reason`; each faction's `prewar_capital`, `declaration_pressure`, `declaration_turn`; and `political.phase0_relationships`, `phase0_events_log`. Kept (war code reads them): `meta.war_start_turn`, `meta.game_over`, `meta.outcome`, `faction.declared`. The v3 step keeps writing its old defaults so every older save still steps through the chain. The validator marks the v3 peace fields `retiredAtVersion: 41`, still type-checks them before v41, and rejects any deleted field on a v41 state. Removed from the player-visible meta/political projections. The end-of-run historical-alignment diagnostic drops its `prewar_capital` column (a constant 100/70/40). The startup snapshot is rebuilt at v41.

**Hash-moving.** Every save loses the deleted keys and changes `schema_version`; the negotiation b371 digests are re-pinned for v41. No sim behaviour is meant to change; the parent lane runs the hash proofs.

The ~200 `if (phase !== 'war') return` guards are intentionally left: with PhaseName narrowed to 'war' they are harmless no-ops; do not 'fix' them.

**Tests.** New `tests/peace_phase_retired.test.ts` and fixture `tests/fixtures/save_migration/v40_peace_phase_fields_retired.json` (carries every deleted field, on all three factions). Deleted: `turn_pipeline_order`, `turn_pipeline_weekly_increment`, `turn_pipeline_determinism_smoke`, `alliance_phase0_handoff`, `ui/peace_status_panel_copy`; the peace cases of `early_war_entry_gating` and the "does nothing when phase is peace" cases across the combat, displacement, emergence and pipeline-step suites; the `runOneTurn` tripwire mocks. About 100 test files lose the deleted keys from their state literals. Version pins (schema-freeze, versioned-steps, drift audit, strict-null optional-field floor 598 → 581 / state 222 → 205) updated.

**Docs.** `SAVE_SCHEMA_EVOLUTION.md` v41 entry. The engineering entrypoint docs (`PIPELINE_ENTRYPOINTS.md`, `CODE_CANON.md`, `REPO_MAP.md`, `PRODUCT_ARCHITECTURE_AUTHORITY.md`, `DETERMINISM_TEST_MATRIX.md`) no longer name `src/state/turn_pipeline.ts` as a live pipeline; dated evidence paragraphs are left as written.

**Not in this change.** Canon documents that describe the peace phase are left for the canon review panel. `tools/claude_plays_vrs/run_commander.ts` and `run_three_commanders.ts` still import `runOneTurn` behind a dead peace branch, and `tools/ui/records_surfaces_browser_proof.mjs` still screenshots the removed peace panel; tools are outside `tsc`, so nothing breaks; they are listed for a follow-up.
