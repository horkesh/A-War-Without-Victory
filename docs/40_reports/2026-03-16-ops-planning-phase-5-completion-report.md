## Overview

## Technical Implementation

### 1. Commander Selection Bridge
To enable communication between the disjointed selection and planning modals, a new property `lastSelectedOfficerId` was added to the `GameStore`.
- **Flow**: User clicks "Select Authority" -> `commanderSelectionContext` is set -> `CommanderSelectionModal` opens -> Selection updates `lastSelectedOfficerId` -> `OpsPlanningModal` detects the update and captures the draft assignment.

### 2. Authorization Pipeline
The `handleAuthorize` method in `OpsPlanningModal.tsx` was implemented to consolidate all staged data:
- **Operation Staging**: Sends a `CorpsOperationOrderPayload` via `stageCorpsOperationOrder`.
- **Commander Assignment**: Triggers `stageAssignOperationCommander` immediately following operation staging, ensuring the backend can link the officer to the newly created operation.

### 3. Tactical Map Resilience
Faced with intermittent external basemap loading issues ("Black Map"), the `OpsMapRenderer` was hardened using local asset data.
- **Layer Injection**: The renderer now dynamically injects OSID-based GeoJSON for settlements and municipal boundaries.
- **Interaction Model**: Precise click handling on `osid-points` ensures that even with a blank background, the tactical grid remains interactive and viable for objective mapping.
