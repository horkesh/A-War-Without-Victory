## Method

Two runs of the 40w scenario with identical inputs:

1. **n0 (baseline)** — `ENABLE_TACTICAL_GROUPS = false` (committed default per ADR).
2. **n1 (smoke)** — `ENABLE_TACTICAL_GROUPS = true` (temporarily flipped; reverted post-run).

With flag on, `classifyAxisOpeningAttack` in `src/sim/combat/sector_offensive_launch_helpers.ts` pre-filters the brigade list passed to `hasAttackFloorParticipant` and `axisHasExecutableOpeningAttack` to `[anchor]` only. Anchor resolution: `axis.main_brigade ?? axis.assigned_brigades[0]` per `tactical_group_config.ts`.

## Interpretation

v1 architectural claim is proven: anchor-only filtering produces zero regression because in every pre-planned op that fires in the 40w window, the anchor (first-listed brigade per ADR-0005 migration rule) IS the eligible brigade that drives gate passage.

This is the expected outcome. The legacy `axisHasExecutableOpeningAttack` returns true on the first eligible brigade encountered via deterministic iteration over `axis.assigned_brigades` — and the anchor sits first in that order. Anchor-only filtering is *more restrictive* than the legacy gate but functionally equivalent when the anchor IS eligible.

The 4 hand-review anchor-mispick cases flagged in ADR-0005 r3 (§Migration of existing pre-planned ops) — Op Podrinje Sweep / `rogatica_sokolac`, Op Drina ↔ Op Podrinje Sweep shared `rs_1st_bratunac` anchor, Op Visegrad JNA-phantom donors, Op Prsten all-JNA-phantoms — are all post-w40 territory. They will surface in 156w+ smoke testing once v2 wires donor mechanics.

## v2 implication

v1 alone does **not** unblock late-war ops (Op Trnovo, Op Pracha River, Op Zvezda 94). v1 is pure scaffolding: it establishes the anchor concept formally in the readiness gate so v2's donor pool mechanic has a clean attachment point.

**v2.0** (donor pool selection + TG formation + v33→v34 schema migration) is the next mandatory step. **v2.2** (combat synthesis) is the calibration-shift stage per the ADR sub-stage ordering.
