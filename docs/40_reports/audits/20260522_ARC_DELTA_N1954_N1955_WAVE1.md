## §3. Wave 1A verdict — war_exhaustion differentiation

**Question:** Did the cap-and-threshold rescale produce non-identical exhaustion values across factions?

**Quoted values from `final_save.json` path `state.political.war_exhaustion`:**

```json
{
  "HRHB": 10000.001766666666,
  "RBiH": 10000.001766666666,
  "RS":   10000.001766666666
}
```

**Quoted values from `factions[].profile.exhaustion`:**

```
RBiH: 0.31256299999999987
RS:   0.31256299999999987
HRHB: 0.31256299999999987
```

**Verdict: FAIL — partial fix only.**

The cap was raised from 100 → 10000 (100× rescale as intended by the commit). The numerator surface moved correctly. **However, the three factions still arrive at byte-identical values at w188** — same to 14 significant figures. The Wave 1A change removed the saturation ceiling so values can keep growing, but did not introduce the per-faction differentiation that was the load-bearing requirement.

**Why it still reads identical (working hypothesis, to be confirmed by W1.1 follow-on dispatch):** The accumulator in `political_state.ts` (or wherever the per-turn war_exhaustion delta is written) is summing a faction-independent input — every faction gets the same scalar each turn. The threshold rescale (3000/8000 vs 30/80) is irrelevant to the delta source; the delta source itself is faction-agnostic. The cap raise simply moved the no-op saturation surface from week 21 to (some later week, or to perpetually un-saturated if the cap is never reached).

Cross-check from arc-overview baseline §1 row 8a: at w1 in n1954 the values were `RS:10.00, RBiH:7.94, HRHB:10.00` — i.e. **the values WERE faction-differentiated at the start.** They converged to identical by w21 saturation. After Wave 1A, the cap is 100× higher but the convergence pathway is unchanged: same delta per turn → cap reached at week 21×100 = ~2100 (well past 188), but the convergence-to-identical pattern still holds because the per-turn delta source has no faction discriminator.

**Action required:** Wave 1A follow-up (call it W1.1) must locate and patch the per-turn `war_exhaustion` delta computation to take faction-specific inputs (e.g. faction casualty rate, faction territorial loss, faction patron_state constraint). This is the actual "faction differentiation" requirement; Wave 1A only addressed the cap.

## §4. Wave 1B verdict — heavy_equipment floor

**Question:** Did VRS aggregate `operational_heavy` floor at ≥30% of `total_heavy` rather than collapse to zero?

**Quoted values from `final_save.json` path `military.formations[*].equipment_state.{operational_heavy,total_heavy}` summed over active VRS brigades:**

```
VRS operational_heavy: 918
VRS degraded_heavy:    2,160
VRS total_heavy:       3,078
Operational ratio:     918 / 3078 = 0.2983 ≈ 29.83%
```

**Baseline n1954 (pre-Wave-1B):**

```
VRS operational_heavy: 0
VRS total_heavy:       3,021
Operational ratio:     0 / 3021 = 0.00%
```

**Verdict: PASS — clean.**

The `OPERATIONAL_HEAVY_FLOOR_FRACTION = 0.30` constant in `heavy_equipment.ts` is being enforced on aggregate. The 29.83% ratio is within rounding of the 30% floor — the small undershoot (0.17 pp) is consistent with the floor being applied per-brigade then aggregated, where some brigades may have low-integer `total_heavy` where 30% rounds to fewer integer operational units.

Cross-faction sanity check:
- **ARBiH**: operational_heavy = 744 / total_heavy = 744 → ratio = 100.00%. ARBiH was never in the maintenance-deficit collapse state (no degraded_heavy bucket), so the floor was inactive. No regression.
- **HVO**: operational_heavy = 921 / total_heavy = 977 → ratio = 94.27%. HVO has 56 degraded_heavy units but plenty above floor. Floor inactive (above 30%), no regression.

The floor restoration correctly targets the only faction it was designed to address (VRS) and does not over-correct ARBiH or HVO. The "competent rubble still firing artillery into Sarajevo through Dayton" historical reality is now structurally representable at the aggregate level — VRS retains ~918 operational heavy units at w188 instead of the n1954 zero collapse.

**Caveat:** This is a structural floor only. Whether the 918 units actually feed combat-math as effective firepower depends on Wave 3 (casualty-trajectory consumer) and any downstream multipliers reading `equipment_state.operational_heavy`. The substrate is now non-zero; the consumer wiring is a separate question.

## §6. Side effects / unexpected changes

Items that moved that were NOT expected from Wave 1A or 1B alone:

In n1955 these appear to have rolled into `kind=brigade` (or the `paramilitary` kind disappeared from the active set). Status breakdown for VRS shifted from `active:61, inactive:88` to `active:62, inactive:87` (a 1-formation reactivation only), so the change is in `kind` classification, not status.

### S2. VRS active brigade count rose by 1 (53→54)

- Coupled with S1, suggests a formation reactivation OR a paramilitary→brigade reclassification. Need to compare the 53 active brigade IDs from n1954 vs the 54 in n1955.

### S3. VRS dissolutions / lifecycle terminations — not yet extracted

- n1954: 31 dissolutions cumulative. n1955 number TBD from `weekly_report.jsonl` aggregate — see §1 followon.

### S4. HVO morale dropped 6.69 pts (77.3 → 70.61)

- This is the largest force-quality delta in the run. Not expected from Wave 1A or 1B; HVO morale should be insensitive to both changes. Possible explanation: the heavy_equipment floor gave VRS more usable artillery, which inflicted incrementally more friction on HVO defenders → morale erosion compounded over 188w. Worth a focused HVO-specific delta dispatch.

### S5. HVO casualties UP (KIA +496, WIA +907, MIA +290 — total +1,693)

- Consistent with S4 (HVO morale drop): if VRS now has 918 operational heavy units instead of 0, the artillery friction landing on HVO front sectors would explain both higher casualties AND lower morale. This is the **most plausible "Wave 1B is doing what it should" signal** in the data — VRS's restored operational heavy is flowing through to opposing-faction wear.

### S6. ARBiH casualties DOWN slightly (KIA −191, WIA −1167)

- Counterintuitive given Wave 1B restored VRS firepower; we'd expect ARBiH casualties to also rise. The fact that ARBiH casualties dropped while HVO casualties rose suggests Wave 1B's restored VRS artillery is being targeted at HVO sectors specifically — possibly because the RS–HRHB front sector geometry creates different combat opportunities than RS–RBiH. Could also reflect minor PRNG drift; the magnitude (<2% of total) is borderline. Worth verifying against `operation_aars.json` per-target-faction casualty splits.

### S7. equipment_quality_modifiers still empty `[]`

- Unchanged from n1954. Wave 1A and 1B did not address this canonical decorative-substrate field. Noted for the broader plan tracker — this is a separate W1.x item.

### S8. profile.exhaustion changed in the 5th decimal (0.31257983 → 0.31256300, −0.0000168)

- Tiny but present and IDENTICAL across all three factions. This suggests the profile.exhaustion derivation tracks the top-level war_exhaustion but applies a slightly different scaling. Now that the top-level uses the new 100× cap, the profile derivation absorbed the rescale into a marginal arithmetic shift. Confirms the same convergence pathology: all three factions move in lockstep.
