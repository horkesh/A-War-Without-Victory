## 1. Scope + methodology

### 1.1 Scope

WCAG 2.1 AA conformance audit across the React tactical-map shell (`src/ui/map/`), the canonical shared modal wrapper (`src/ui/shared/Modal.tsx`), and the vanilla-TS Warroom shell (`src/ui/warroom/`). Auxiliary surfaces (Codex, Decision Room, settings, forms, replay) included by reference. Map-canvas and deck.gl layer a11y (typically a "rich graphics" surface that needs a text-equivalent) called out separately.

WCAG AA targets:
- Color contrast: 4.5:1 for normal text, 3:1 for large/UI elements.
- Keyboard navigation for all interactive controls (Tab order, Enter/Space activation, ESC dismissal).
- ARIA labelling for ambiguous controls (icon buttons, custom widgets).
- Focus management for modal stack and route transitions.
- Reduced-motion support where animation is non-decorative.
- Live-region announcements for status / async results.
- Screen-reader landmarks (`<main>`, `<nav>`, `<aside>`).
- Form labels (`<label htmlFor>` or `aria-labelledby`).

## 2. Current-state strengths (a11y posture is partly already there)

It is important to ground the gap analysis in what is already correct. AWWV's UI is **substantially better than typical game UIs** on a11y because:

1. **Canonical shared `<Modal>` wrapper exists** (`src/ui/shared/Modal.tsx`, 309 lines). Already implements:
   - `role="dialog"` + `aria-modal="true"` on the panel.
   - `aria-labelledby` / `aria-label` props (when callers supply them).
   - ESC-key dismissal at window level (gated by `dismissible`/`closeOnEscape`).
   - Focus capture on open (first focusable in panel, fallback to panel itself).
   - Focus restore on close (to the originator).
   - Tab-trap inside the panel (cycles via Shift+Tab).
   - `tabIndex={-1}` on panel for programmatic focus.
   - 12+ modals already migrated per `LANE-V094-MODAL-MIGRATION` (`AdvanceTurnModal`, `AttackConfirmation`, `CommanderSelectionModal`, `DaytonNegotiationModal`, `EventDecisionModal`, `GameOverModal`, `OperationBriefingModal`, `PeacePlanModal`, `RecruitmentModal`, `SidePickerOverlay`, `TurnAftermathModal`, `WarSummaryModal`). They pass `ariaLabelledBy` referencing internal heading IDs.

2. **Real `<button>` elements dominate.** 294 occurrences across 94 files. Native keyboard + SR support without custom handlers. Custom-button anti-patterns (`<div onClick>`) appear in only 4 files.

3. **Canonical color palette exists** (`src/ui/shared/factionPalette.ts`). Single source of truth derived from `FACTION_GLOW_RGB`. Tailwind `tailwind.config.ts` has named status tokens (`status-good`, `status-warn`, `status-danger`) — semantic, not literal hex.

4. **z-index canonicalized** (`src/ui/shared/zIndex.ts`). Frozen tier registry; modal-stack ordering deterministic; no a11y-breaking layer races.

5. **`role="status"` + `aria-live="polite"` already present** on:
   - `LoadingSkeleton` (`role="status"`, `aria-live="polite"`, `aria-busy="true"`, `aria-label`).
   - `LoadErrorToast` (`aria-live`, `role`).
   - `EmptyState` (`role`, `aria-label`).

6. **Focus management primitives already in `<Modal>`.** `LANE-V094-MODAL-WRAPPER` (P1-J in the predecessor audit) already shipped the focus return + tab trap. This is the highest-leverage a11y primitive in any GUI app, and it is already done.

The gap is therefore **mostly about coverage and discipline**, not foundational missing infrastructure.

## 7. Stop triggers (binding)

The following STOP triggers apply across all 5 lanes:

1. **Visible-behavior regression** — if any a11y fix changes visible visual output in a way the user notices (color drift, layout shift, animation removal where motion was meaningful), REVERT and re-plan. Visual diff baseline (Playwright screenshot) is the gate.

2. **Tutorial onboarding anchor breakage** — if any a11y fix removes or relocates a `data-tutorial-step` anchor (per `onboardingSteps.ts`, 2 occurrences in `WarSummaryModal`, `WarroomStatusBar`, `AdvanceTurnModal`, `WarCostSummary`, `PresidentialDecisionRoomPanel`, `TurnAftermathModal`, `ArmyHQModal`, `PresidentialToolbar`, `OnboardingOverlay`), STOP and re-plan. Spotlight resolution depends on these.

3. **Public component-API breaking change** — if WCAG conformance requires changing a `Modal` / `Tab` / form-component public prop signature in a way that breaks existing callers, STOP and design discussion. Prefer additive props with sensible defaults.

4. **Determinism / sim-path bleed** — if any lane's diff stat shows a file under `src/sim/`, `src/state/`, `data/scenarios/`, `data/derived/`, `docs/10_canon/`, REVERT the bleed and re-confirm the lane's file ownership.

5. **Test-suite regression > 0** — if `npm run test:vitest` regresses (>0 new failures), STOP. Diagnose root cause before continuing the lane.

## 8. Test fixture pattern

### Recommended: `axe-core` integration

The codebase already uses Playwright (per `memory/playwright_visual_verification.md`, v1.59.1). Add `@axe-core/playwright` as a dev dependency and ship one canonical helper:

```ts
// tests/e2e/_helpers/a11yScan.ts
import { AxeBuilder } from '@axe-core/playwright';

export async function expectNoA11yViolations(page) {
  const results = await new AxeBuilder({ page })
    .withTags(['wcag2a', 'wcag2aa'])
    .analyze();
  expect(results.violations).toEqual([]);
}
```

Per-lane Playwright tests then call `expectNoA11yViolations(page)` after rendering the relevant surface.

### Hand-rolled assertion patterns (where axe-core can't help)

- **Color contrast (LANE D):** sRGB relative-luminance computation in pure JS (~30 LOC). No external dep needed.
- **Focus management (LANE A):** jsdom + RTL + `document.activeElement` assertions.
- **Tablist arrow-key cycling (LANE C):** `fireEvent.keyDown(el, { key: 'ArrowRight' })` → assert active tab updated.
- **Reduced-motion media query (LANE D):** parse `globals.css` text for the literal media-query string at the head; or Playwright `page.emulateMedia({ reducedMotion: 'reduce' })` + `getComputedStyle` assertion.
