# 1.0 Robustness Landmine Audit — latent serialize / divergence / old-save crash hunt

**Date:** 2026-06-09
**Type:** READ-ONLY AUDIT (findings + fix sketches only — no code changed)
**Scope:** Latent crashes/corruptions invisible to the historical-default 188w calibration run but reachable on (a) the D2 full-campaign start→Dayton playtest, (b) emergent/free-war divergent games, or (c) loading old/divergent saves.
**Archetype:** PR #358 — `buildHomeDistanceCache` stored raw `Infinity`, which `JSON.stringify` turns into `"null"` (corruption) and which broke the structural/determinism hash on divergent games. Fix was `HOME_DISTANCE_UNREACHABLE_HOPS=99`. This audit hunts that CLASS.

The dominant residual risk is the **#358 class re-occurring**: the central serializer has no finiteness guard, so any future (or divergent-data) non-finite number that reaches a persisted `GameState` field silently corrupts the save and/or moves the save byte-hash. #358 was a point-fix at one producer; the *serializer itself* still does not defend.

## P1 findings

### P1-A — Central serializer silently corrupts on non-finite numbers (no guard)
**File:** `src/state/serializeGameState.ts:36-76` (`toDeterministicJsonValue`), consumed by `serializeGameState` → `JSON.stringify`.
**Trigger:** Any `number` field on `GameState` holding `NaN`, `Infinity`, or `-Infinity` is passed straight through `toDeterministicJsonValue` (it only special-cases `Map`/`Set`/`Array`/object, and returns primitives verbatim). `JSON.stringify(NaN)` and `JSON.stringify(Infinity)` both emit `null`. Result: the field silently becomes `null` on save (corruption — a later load may fail the validator's `isFiniteNumber`/`isFiniteNonNegativeNumber` checks, or read `null` as a number), AND the in-memory→serialized round trip is lossy so the `final_state_hash` diverges. The historical-default 188w run never produces a non-finite persisted field, so this is invisible today; it is exactly how #358 escaped detection until a divergent game hit it.
**Why historical-default misses it:** calibration is one fixed path where every numeric accumulator stays finite. D2 / emergent games exercise event-effect deltas, collapse multipliers, and graph-distance sentinels on OSID topologies the calibration path never reaches.
**Confidence:** The gap in the serializer is **confirmed by inspection**. Whether a *currently-reachable* producer feeds it a non-finite value is **unconfirmed** (the known producer was fixed in #358); this finding is about the missing systemic defense, which is what lets the next P2 below become a live corruption.
**Fix sketch:** Add a central finiteness guard in `toDeterministicJsonValue` for the `number` branch: if `!Number.isFinite(value)`, either (a) throw a descriptive error naming the offending key-path (fail-loud, preferred for the determinism contract so a non-finite value is caught at save time rather than silently nulled), or (b) canonicalize to a documented sentinel. A fail-loud throw is the smaller, safer change and converts a silent corruption into an immediately-diagnosed bug. Add a unit test feeding `{x: Infinity}`, `{x: NaN}` and asserting the throw. This is the single highest-leverage fix: it turns the entire #358 *class* from "silent latent corruption" into "loud, located, at-save-time error."

### P1-B — Event-effect numeric deltas reach persisted fields with no finiteness guard
**File:** `src/state/...` reached via `src/sim/events/apply_effects.ts` — `clamp()` (line 39-41), `applyMoraleChange` (151), `applyCohesionChange` (162), `applySupplyDelta` (171), `applyHumanitarianImpact` (180), `applyPatronPressure` (188), `applyAllianceChange` (203-208), `applyNegotiationBreakdown` (299+).
**Trigger:** `clamp(value, min, max)` is `Math.max(min, Math.min(max, value))`, which does NOT trap `NaN` — `clamp(NaN, 0, 100) === NaN`. Effect deltas (`effect.delta`, `effect.war_crimes_delta`, `effect.multiplier`, etc.) are typed `number` but are **never runtime-validated for finiteness** before being added to and written back into `formation.morale`, `formation.cohesion`, `general_supply_reserve[faction]`, `negotiation.capital[*].war_crimes_events`, and `political.war_alliance_rbih_hrhb`. A non-finite delta (malformed/divergent event definition, future data-driven or computed-delta event, or an effect whose delta is itself derived from a divide-by-zero upstream) writes `NaN` into a persisted formation/state field → then hits P1-A and corrupts the save / moves the hash. The accumulator fields (`war_crimes_events`, `general_supply_reserve`) are also unbounded `+=` with no clamp, so a non-finite or runaway value persists indefinitely.
**Why historical-default misses it:** every shipped historical event effect carries a hand-authored finite delta, so the calibration path is always finite. Emergent/free-war branching and any future data-driven event authoring can introduce a delta the calibration corpus never exercises.
**Confidence:** The missing guard is **confirmed**; reachability with a non-finite delta is **unconfirmed — needs a malformed/divergent event def or a computed-delta event to trigger**. Rated P1 because it is the most plausible live feeder of P1-A and writes directly into serialized formation state.
**Fix sketch:** Harden `clamp` to `Number.isFinite(value) ? Math.max(min, Math.min(max, value)) : min` (mirrors the good model already in `commander/allocate.ts:104` `computeMustHoldMultiplier`, which explicitly collapses `NaN`/`Infinity` to its floor). Separately, guard the un-clamped accumulators (`applySupplyDelta`, `applyHumanitarianImpact`) with a `Number.isFinite(delta)` early-return. Optionally add a one-time validation of effect-definition numeric payloads at event-load time so a bad data file fails loud rather than at serialize. Faction-agnostic, no calibration impact (finite deltas are unchanged).

## P2 findings (latent)

### P2-A — Same-version save missing a future hard-required field (the #360 class is still open structurally)
**File:** `src/state/validateGameState.ts:3210-3293` (`VERSION_REQUIRED_FIELDS`) + `:3324-3338` (enforcement) + `src/state/serialize.ts:258-337` (`canonicalizeCurrentFields`).
**Trigger:** The validator hard-requires every `v3..v36` field be present when `schema_version >= introducing-version`. For *sub-version* saves this is satisfied by `applyMigrations` backfilling. But a **same-version** state (an in-memory factory state, or a divergent-game save written at `CURRENT_SCHEMA_VERSION`) that lacks a required field is **rejected on load** — because `applyMigrations` only runs migrations *below* the current version. This is exactly the v36 `displacement_flows_by_osid` break that #360 patched via `optionalWhenAbsent: true` + load-side seeding in `canonicalizeCurrentFields`. Today only `v36` carries `optionalWhenAbsent`; the structural hazard remains for the *next* field added this way.
**Why historical-default misses it:** the calibration harness builds state at `CURRENT_SCHEMA_VERSION` and populates fields during the run, so the field is always present at save time.
**Confidence:** Confirmed as a process/structural hazard; no currently-shipping field is broken (v36 is mitigated).
**Fix sketch:** This is a **convention to enforce, not a code bug today.** Add a checklist/test invariant: any new `VERSION_REQUIRED_FIELD` for a lazily-initialized/optional read-model MUST either (a) be seeded on every load in `canonicalizeCurrentFields` AND marked `optionalWhenAbsent: true`, or (b) be written by all current-version state factories. Consider a CI test that constructs a minimal current-version state via the new-game factory and asserts it passes `validateGameStateShape({requireVersion: CURRENT_SCHEMA_VERSION})` — that test would have caught #360 before merge.

### P2-B — `applyAllianceChange` persists a float that can be non-finite if delta is non-finite
**File:** `src/sim/events/apply_effects.ts:201-208`.
**Trigger:** `war_alliance_rbih_hrhb` is one of the few *float* persisted fields (range [-1,1]). It is set via `clamp(current + delta, -1, 1)` then re-clamped against alliance-lock bounds. A non-finite `delta` survives `clamp` (P1-B) and a non-finite value compares `false` against the bound checks (`next > ceiling` is `false` when `next` is `NaN`), so `NaN` persists. This is a strict subset of P1-B but called out because it is a *float* field (most others are integer-clamped) and floats are the platform-divergence-sensitive class the structural fingerprint deliberately excludes — a non-finite here is doubly bad.
**Confidence:** Same as P1-B — unconfirmed reachability, confirmed missing guard.
**Fix sketch:** Covered by the P1-B `clamp` hardening; no separate change needed once `clamp` traps `NaN`.

### P2-C — `Math.max(...op.axes.map(...))` on a possibly-empty array → `-Infinity`
**Files:** `src/sim/combat/army_reserve_system.ts:561` (`Math.max(...op.axes.map(a => a.momentum ?? 0))`); compare safe `src/sim/combat/commander/plan.ts:290` (`Math.max(...zones.map(z => z.deficit), 0)`).
**Trigger:** `Math.max()` with no args returns `-Infinity`. `plan.ts:290` is **guarded** (`zones.length > 0 ? … : 0` AND includes a `, 0` seed) — safe. `army_reserve_system.ts:561` spreads `op.axes.map(...)` with **no empty-guard**: if `op.axes` is `[]` (an operation with zero axes — possible on a divergent/aborted op), `Math.max()` returns `-Infinity`. The value is read into a local `momentum` for reserve-priority comparison; it is **not** obviously persisted (it gates reserve dispatch), so impact is a mis-prioritization, not a guaranteed corruption — UNLESS the value flows back into a stored `op.momentum`.
**Confidence:** `-Infinity` production is confirmed for an empty `op.axes`; whether `op.axes` is ever empty at this call site, and whether the result is persisted, is **unconfirmed — needs a runtime check on a divergent aborted-op state.**
**Fix sketch:** Seed the reduce: `op.axes.length ? Math.max(...op.axes.map(a => a.momentum ?? 0)) : 0`, matching the safe `plan.ts:290` pattern. Trivial, faction-agnostic.

### P2-D — Graph-distance `Infinity` sentinels in transient structures (audit-clean, watch for future persistence)
**Files (representative):** `src/sim/combat/army_reserve_system.ts:111,119,138,386,668,901`; `attack_retreat_displacement.ts:152,188-189`; `combat_math.ts:259`; `operation_reinforcement.ts:70`; `zone_detection.ts:368,396`; `bot_brigade_movement_ai.ts:231,260-261`; `brigade_assignment.ts:787-809`; `commander/emit.ts:1017-1018,1588`.
**Trigger:** Many BFS/distance helpers return `Infinity` for "unreachable," and several `let best = Infinity` accumulators / `-Infinity` score seeds. Inspected sample: all are **consumed locally** (compared, used to `continue`/skip, or assigned into transient candidate arrays that are not serialized) — same safe pattern the bounding-box `Infinity`s in UI use. This is the exact shape that bit #358 (`computeOsidGraphDistance` returns `Infinity`), so it is the highest-yield place for the NEXT instance to appear.
**Confidence:** Sampled sites are confirmed transient/local. Not exhaustively traced — **unconfirmed that none reaches a persisted field**; the #358 fix demonstrates one *did* (the home-distance cache). The general defense is P1-A.
**Fix sketch:** No per-site change required now. The P1-A central serializer guard is the systemic backstop. As a belt-and-suspenders convention: any new function that returns a graph distance should clamp to a finite sentinel (e.g. reuse `HOME_DISTANCE_UNREACHABLE_HOPS`) at the point where the value could be stored, not where it is computed.

### P2-E — Cumulative displacement / log aggregates over a full campaign (bounded, but verify)
**Files:** `src/state/displacement_event_log.ts:54-156`; aggregates `displacement_humanitarian_aggregates`, `displacement_origin_dest_arrivals`, `displacement_flows_by_osid`, `displacement_recent_by_turn`.
**Trigger:** The per-turn `displacement_event_log` IS cleared at end-of-turn (`war_phases.ts:3945-3957`, `clear-displacement-event-log` step) — **confirmed not unbounded.** The cumulative aggregates are analytically bounded (`displacement_flows_by_osid` ≲744 OSID keys; `displacement_humanitarian_aggregates` ≲3 factions × ethnicities; `displacement_recent_by_turn` grows 1 key/turn ≈188 over a full campaign; `displacement_origin_dest_arrivals` ≲ muns²). None is per-event-unbounded. `turn_summaries`, `operation_history`, `event_causality_log`, `event_decision_log` grow per-turn/per-event but are bounded by campaign length (~188 turns to Dayton).
**Why historical-default misses it:** it doesn't — the 188w run exercises the same growth. This is **not a latent landmine**; logged for completeness because the prompt flagged it.
**Confidence:** Confirmed bounded for a Dayton-terminating campaign. The only residual: a free-war game that runs *past* Dayton with no termination would keep growing `operation_history`/`event_causality_log` — but the campaign terminates at Dayton, so out of scope.
**Fix sketch:** None needed. If post-Dayton open-ended play is ever added, cap or window `operation_history` and `event_causality_log`.

## Verified-safe (closed) — checked and found robust

1. **Division-by-zero in displacement/population math** — `src/state/displacement.ts:670-678`, `population_share.ts:24-29`, `displacement_takeover.ts:241-242` all guard `entry.total <= 0` with a fallback, and `displacement_takeover.ts:242` additionally wraps the result in `Number.isFinite(share) ? … : null`. Exemplary defensive code. No fix.
2. **Save migration backfill completeness** — `src/state/save_migration.ts` v1-v36: every `VERSION_REQUIRED_FIELD` has a corresponding migration that `ensureRecord`/`ensureArray`-seeds it for sub-version saves; all migrations are pure in-place patches with sorted iteration. No deref/non-null-assertion hazard found loading an old (v<36) save through `applyMigrations`. (Same-version hazard is P2-A.)
3. **Map/Set serialization** — `serializeGameState.ts:44-59` explicitly converts `Map`→sorted plain object and `Set`→sorted array (commander v0.8 state uses Maps); no Map/Set silently becomes `{}`. Robust.
4. **Determinism leaks** — none in `src/sim` or `src/state`. The lone `Date.now()` is in the live LLM client (`anthropic_client.ts`), not the deterministic pipeline.

## Recommended fix ordering (all out of scope for this read-only audit)

1. **P1-A** — central serializer finiteness guard (fail-loud throw). Single highest-leverage; converts the whole #358 class from silent corruption to located at-save error. Requires a determinism baseline re-verify (should be byte-identical on the historical path since no non-finite values occur there).
2. **P1-B / P2-B** — harden `clamp` in `apply_effects.ts` to trap `NaN` (mirror `computeMustHoldMultiplier`), guard un-clamped accumulators. Calibration-flat (finite deltas unchanged).
3. **P2-C** — seed the `army_reserve_system.ts:561` `Math.max` spread. Trivial.
4. **P2-A** — add the current-version-factory validator CI test as a #360-class regression guard (process/test, not engine).

All proposed fixes are Ring-1 / faction-agnostic / no §6 (enclave-guard) surface. Each should be verified 40w + 188w byte-identical before merge, since the historical path produces no non-finite values and the guards are no-ops on finite input.
