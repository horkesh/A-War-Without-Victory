# Implemented Work — HoI Map Renderer: Comprehensive Report

**Date:** 2026-02-22
**Status:** Functional; front line work handed off to external agent for cleanup
**Scope:** Full HoI-style 2.5D WebGL map — terrain, political control, front lines, ZoC, formations, labels, interaction, UI components

## Overview

Built a complete Hearts of Iron-style 2.5D strategic map renderer using Three.js with orthographic camera. The map displays the Bosnian theatre with hypsometric terrain coloring, hillshade relief, rivers, roads, semi-transparent political control fills, HoI4-style painted band front lines, formation markers, settlement labels, and interactive click/hover/selection.

---

## Part 1: Core Renderer (`HoIMapRenderer.ts`, ~1760 lines)

### 1.1 Terrain Mesh & Texture

- 3D terrain mesh from 1024x1024 heightmap (elevations -2m to 2404m)
- UV-mapped mesh built by `TerrainMeshBuilder.buildTerrainMesh()`
- Texture generated by new `HoITerrainTexture.ts` (see Part 2)
- `polygonOffset` on terrain material to prevent z-fighting with control layer

### 1.2 Political Control Layer

Single merged mesh with per-vertex faction colors, covering the entire game world:

- **Global vertex deduplication table**: shared boundary vertices between adjacent settlements are identical in 3D, eliminating gaps and overlaps
- **Faction colors at 75% opacity**: RS (`0xb23c3c` red), RBiH (`0x419150` green), HRHB (`0x3773af` blue)
- **NULL_COLOR** (`0xacbe91` muted sage-green): matches terrain lowland base, blends naturally at 75% opacity
- **Triangle subdivision** (level 3): subdivides each polygon triangle to drape smoothly over heightmap terrain
- **Raycast hit-testing**: `featureByTriIndex` mapping allows click/hover on individual settlements

### 1.3 Camera & Controls

- **Orthographic camera** with tilted 2.5D view (default 20°)
- **Zoom**: Scroll wheel, frustum scales (not FOV); bounds 0.4 (closest) to 3.2 (furthest)
- **Pan**: Left-click or middle-click drag; cursor changes to "grabbing"
- **Tilt**: Right-click drag on vertical axis; adjustable 10° (top-down) to 50° (steep oblique)
- **Home key**: Reset to default (pan 0,0; zoom 2.8; tilt 20°)
- **ResizeObserver**: Syncs canvas to container in real-time

### 1.4 Click, Hover & Selection

- Raycasting against control mesh for settlement identification
- **Hover tooltip**: Fires callback with feature properties + screen coordinates; 300ms delay to avoid flicker
- **Click selection**: Pins tooltip, highlights settlement border with golden silhouette (boundary edge extraction, slight Y lift)
- Hover suppressed during active panning/tilting

### 1.5 Settlement Labels (3D Billboard Sprites)

- Floating labels as Three.js billboard sprites (not baked into texture)
- Canvas-drawn text with white halo for readability
- Cities (pop >= 15k): larger font, visible at all zoom levels
- Towns (pop >= 5k): smaller font, fade at far zoom
- Scale dynamically with camera distance

### 1.6 Formation & Order Markers

- `setFormations()`: Brigade/corps marker billboards with faction color bands and abbreviated names; corps scaled 1.5x larger
- `setOrderArrows()`: Quadratic Bezier curves from origin to destination with faction coloring
- Additional overlay methods: `setLabels()`, `setStrategicPoints()`, `setEnclaveRings()`

### 1.7 Layer Visibility

Six toggleable layers controlled by the MapModeToolbar (F1-F6):

| Layer | Key | Content |
|-------|-----|---------|
| Terrain | F1 | Hillshade + hypsometric base mesh |
| Political | F2 | Settlement control fills + borders |
| Front Lines | F3 | Painted band fronts + assignable segments |
| Formations | F4 | Brigade/corps markers + order arrows |
| Labels | F5 | Settlement names |
| ZoC | F6 | Enemy zone of control overlay |

`applyLayerVisibility()` propagates toggle state to all meshes/sprites immediately.

## Part 2: Terrain Texture (`HoITerrainTexture.ts`, ~256 lines)

New file, fork of `DayOpsTexture.ts` with warm parchment/green palette.

Builds a 2048x2048 canvas texture with:

1. **Hypsometric elevation coloring** (11-stop gradient):
   - 0m: muted sage-green (`#acbe91`) — lowlands
   - 100m-400m: olive-green foothills
   - 800m-1300m: tan-brown mid-hills
   - 2000m+: grey-brown peaks

2. **Hillshade overlay** from heightmap normals:
   - NW sun direction
   - Stronger blend factor (0.65-1.15) to remain visible through 75% opacity control layer

3. **Rivers** (blue-grey, `rgba(90,120,145,0.6)`):
   - Major rivers (Bosna, Drina, Neretva, Sava): 4px width
   - Streams: 0.8px at 0.25 opacity

4. **Roads** (ochre/brown, subdued):
   - Motorway/trunk/primary/secondary at varying widths (2.5px down to 1px)
   - Dark casing layer underneath

5. **Settlement dots** (NATO convention):
   - Cities >= 15k: 2.5px radius black filled circles
   - Towns >= 5k: 1.8px radius
   - Villages >= 2k: 1.0px radius

## Part 3: Front Lines — HoI4 Painted Bands

### 3.1 Contact Graph Loading

Fetches `operational_contact_graph.json` (3259 edges, 753 nodes) in parallel during `init()`. This provides the adjacency structure between operational settlements.

### 3.2 Shared Border Geometry

New `computeSharedBorders(edges)` method:
1. For each contact graph edge, builds vertex set from settlement B's outer ring(s)
2. Walks settlement A's ring(s), collects vertices shared with B
3. Stores as `SharedBorder { a, b, points }` keyed under both operational ID pair and canonical SID pair

### 3.3 Canonical-to-Operational SID Mapping

Extended `computeCentroids()` to map ALL `constituent_sids` from each operational feature to the parent OSID. Critical because front edges from saves use canonical SIDs (`S100196`) but the renderer uses operational IDs (`op:banovici:seona`).

### 3.4 Painted Band Rendering (`setFrontEdges()` rewrite)

For each front edge where two factions meet:
- **Faction A half-band**: Offset toward A's territory, A's faction color at 0.5 opacity
- **Faction B half-band**: Offset toward B's territory, B's faction color at 0.5 opacity
- **Dark center line**: `0x14120f` at 0.7 opacity along the actual border

**Key constants:**
- `BAND_HALF_WGS = 0.0012` (WGS degrees per half-band)
- `CENTER_HALF_WGS = 0.00015` (dark separator half-width)

**Inner function `buildRibbonAlongBorder()`**: Creates quad strips along border vertices, samples terrain heightmap per vertex, lifts 0.004 above terrain.

**Perpendicular direction**: Uses centroid of settlement A vs border midpoint dot product to determine which side is "toward A".

**Deduplication**: `drawnOpBorders` Set prevents rendering the same operational border multiple times.

**Internal edge filtering**: Edges where both canonical SIDs resolve to the same OSID are skipped.

### 3.5 Faction Side Info Pass-Through

`map_hoi.ts` updated to pass `side_a`/`side_b` from loaded game state through to the renderer. Previously these fields were stripped.

### 3.6 Statistics

```
3868 front edges total
 808 unique operational borders drawn as painted bands
1414 edges deduplicated (same operational border)
1505 internal edges skipped (both SIDs in same OSID)
 141 edges fell back to centroid-to-centroid ribbon
   0 edges completely unresolvable
```

## Problems Encountered and Failed Approaches

### Problem 1: Blank Map on Load

**Symptom:** Map area was completely blank while WebGL initialized asynchronously.

**Fix:** Added `MapPlaceholder` — a 2D canvas fallback that renders immediately, then hides when WebGL succeeds. Map area is never blank.

### Problem 2: Orthographic Zoom Not Working

**Symptom:** Scroll wheel had no visible effect on zoom level.

**Root cause:** Was trying to modify camera FOV, but orthographic cameras don't use FOV — they use frustum bounds.

**Fix:** Zoom now scales the orthographic frustum (`left/right/top/bottom`) based on the zoom factor. Bounds clamped to 0.4-3.2.

### Problem 3: Container Sizing Mismatch

**Symptom:** Renderer canvas didn't match the actual container dimensions, causing stretching or black borders.

**Fix:** Added ResizeObserver on the map container, calling `renderer.resize()` on every size change. Also triggers resize on next animation frame after init.

### Problem 4: Flat Grey Terrain (No Texture)

**Symptom:** Terrain mesh rendered as a flat grey solid with no visual detail. The inline mesh construction didn't use UV mapping or textures.

**Fix:** Created `HoITerrainTexture.ts` for the texture and switched to `TerrainMeshBuilder.buildTerrainMesh()` which generates proper UV coordinates. Control layer made 75% transparent so terrain is visible underneath.

### Problem 5: Canonical SID vs Operational SID Mismatch (Front Lines)

**Symptom:** Initial front line implementation found only 62 out of 3868 edges had shared border geometry. Almost all fell to fallback rendering.

**Root cause:** Front edges use canonical SIDs (`S100196`) which are constituent members of merged operational settlements. The initial mapping only covered the primary `sid` field, missing hundreds of constituent SIDs.

**Failed approach:** Mapped only the `sid` field from each feature's properties. This missed ~90% of canonical SIDs.

**Fix:** Extended `computeCentroids()` to iterate over `constituent_sids` arrays. Hit rate jumped from 62 to 808 unique borders.

### Problem 6: Massive Overdraw from Duplicate Borders (Front Lines)

**Symptom:** Without deduplication, the renderer created meshes for all 3868 edges, many mapping to the same ~808 operational borders. Stacked semi-transparent quads appeared overly dark.

**Failed approach:** No deduplication — rendered every edge independently.

**Fix:** Added `drawnOpBorders` Set tracking `"border.a__border.b"`. Result: 1414 edges correctly deduplicated.

### Problem 7: Internal Edges Cluttering the Map (Front Lines)

**Symptom:** ~1505 canonical edges where both SIDs belonged to the same merged settlement created tiny ribbons within single settlement territories.

**Failed approach:** These hit the centroid fallback path, creating visual clutter.

**Fix:** Skip edge if both canonical SIDs resolve to the same OSID (`oa === ob`).

### Problem 8: Shared Border Key Mismatch (Front Lines)

**Symptom:** After SID-to-OSID mapping, some lookups still failed because `sharedBorderByEdge` was only keyed by operational ID pairs.

**Fix:** Store each border under BOTH the operational key and the canonical SID key. Added two-stage lookup in `setFrontEdges()`.

### Problem 9: Vite Port Conflict

**Symptom:** `front_line_mockup.html` needed to be served but port 3010 was occupied.

**Fix:** Vite auto-selected port 3011. Mockup accessible at `http://localhost:3011/front_line_mockup.html`.
