## What was built

Four phases of the AWWV architect→executor handoff system v2:

### Phase A — Hook-driven completion

Added `Stop` and `Notification` hooks to `.claude/settings.json`. Both delegate to PowerShell scripts in `tools/architect/hooks/`. Both are **scope-guarded**: they check `AWWV_HANDOFF_RESULT_DIR` and exit 0 silently if the env var is absent (i.e., in any non-handoff Claude session).

- `on_stop.ps1` — fires on `Stop` event: writes `completion_signal.json`, calls `write_review.ps1`, fires Windows notification.
- `on_notification.ps1` — fires on `Notification` event: appends to `notifications.log`, rings terminal bell, writes `status.txt: needs_input` when input is required.

`run_handoff.ps1` now sets `AWWV_HANDOFF_RUN_ID` and `AWWV_HANDOFF_RESULT_DIR` before calling claude, and clears them after completion.

### Phase B — Architect inbox artifact

`write_review.ps1` generates `architect_review.json` in the result dir and copies it to `handoffs/inbox/<run_id>.json`. Fields:

- `task_name`, `run_id`, `session_id` — from `meta.json`
- `branch`, `commit_hash` — from `git log`/`git branch --show-current`
- `files_changed` — merged from `git diff --name-only HEAD` + `git status --short`
- `summary` — first 500 chars of `response.md`
- `completion_block` — text after `## Done` or `Done means:` pattern in response
- `status: "needs_review"` — always set on creation
- `generated_at` — ISO 8601

`run_handoff.ps1` calls `write_review.ps1` unconditionally after all output files are committed. The Stop hook does NOT call `write_review.ps1` — it fires before `response.md` and `meta.json` are written, so the review data would be empty. See architecture note below.

`handoffs/inbox/` created with `.gitkeep`. `handoffs/inbox/*.json` added to `.gitignore`.

### Phase C — Windows notifications

`notify.ps1` implements a three-tier fallback chain:
1. BurntToast module (toast notification — best UX, optional)
2. `msg * /TIME:5` (built-in Windows, no deps)
3. `[console]::beep(800, 300)` + colored `Write-Host`

All wrapped in try/catch — never fails, never blocks the hook.

### Phase D — Review helpers

`list_handoffs.ps1` — scans `handoffs/inbox/*.json`, prints a formatted table sorted by most-recent, highlights `needs_review` items in yellow.

`show_handoff.ps1` — shows full review details for a specific run (or most recent), then prints a paste-ready architect block:

```
============================================================
=== HANDOFF RESULT: <task> ===
Run:    <run_id>
Branch: <branch> | Commit: <hash>
Status: needs_review

SUMMARY:
<first 300 chars>

FILES CHANGED:
- src/...

COMPLETION BLOCK:
<done-means block>
============================================================
```

## How it works end-to-end

```
Architect writes prompt
  → run_handoff.ps1 sets env vars, calls claude -p
    → claude executes task
      → Stop hook fires on_stop.ps1
        → writes completion_signal.json
        → calls notify.ps1 → Windows toast/bell
      → run_handoff.ps1 parses JSON, writes response.md + meta.json (with session_id)
      → run_handoff.ps1 calls write_review.ps1 → handoffs/inbox/<run_id>.json
  → Architect runs list_handoffs.ps1 to see pending items
  → Architect runs show_handoff.ps1 to get paste-ready summary
  → Architect pastes summary into next conversation turn
```

## How to verify

1. Run a handoff (use haiku + tiny budget for cheapness):
   ```powershell
   .\tools\architect\run_handoff.ps1 -PromptFile handoffs\TEMPLATE.md -Name v2-test -Model haiku -MaxBudget 0.10
   ```

2. Check result dir for:
   - `completion_signal.json` (from Stop hook)
   - `architect_review.json` (from write_review.ps1)
   - `notifications.log` (from Notification hook, if any fired)

3. Check inbox:
   ```powershell
   .\tools\architect\list_handoffs.ps1
   ```

4. Inspect summary:
   ```powershell
   .\tools\architect\show_handoff.ps1
   ```

5. Syntax-check all new scripts:
   ```powershell
   powershell -ExecutionPolicy Bypass -Command "
     'on_stop','on_notification','write_review','notify','list_handoffs','show_handoff' | ForEach-Object {
       \$f = if (\$_ -in 'on_stop','on_notification','write_review','notify') {
         \"tools/architect/hooks/\$_.ps1\"
       } else { \"tools/architect/\$_.ps1\" }
       \$null = [System.Management.Automation.Language.Parser]::ParseFile(\$f, [ref]\$null, [ref]\$null)
       Write-Host \"OK: \$f\"
     }
   "
   ```

## Known limitations

1. **Stop hook timing (resolved)**: The Stop hook fires before `run_handoff.ps1` writes `response.md` and updates `meta.json` with the session_id. Early design called `write_review.ps1` from the hook, producing empty summaries and missing session_ids. Fixed: the hook only writes `completion_signal.json` and fires the notification. `run_handoff.ps1` always calls `write_review.ps1` after all output files are committed.

2. **`files_changed` reflects post-completion state**: The diff is taken at hook-fire time, not at task-start. If the executor committed mid-task, `git diff HEAD` will show only uncommitted changes. The `git status --short` merge helps catch staged/untracked files.

3. **BurntToast not pre-installed**: Most Windows machines won't have it. `msg *` is the primary fallback but requires the Messenger service. Terminal bell is guaranteed.

4. **`tests_run` is always false**: Future enhancement — parse test output from `response.md` to detect if the executor ran the smoke-test triad.

5. **Hook fires in all Claude sessions**: The scope guard (env var check) is correct, but if a user manually sets `AWWV_HANDOFF_RESULT_DIR` in their shell, the hook will activate. This is acceptable — the env var is namespaced to AWWV.
