# Local Military State Validate-When-Present

**Date:** 2026-06-06
**Lane:** P1 Optional `GameState` schema contract
**Type:** Save-validation/schema-contract hardening

## Summary

`validateGameStateShape(...)` now rejects malformed present payloads for four optional local military state surfaces:

- `military.brigade_desired_aor_cap`
- `military.og_orders`
- `military.settlement_holdouts`
- `military.faction_officer_maturity`

Absence remains valid, and well-formed present payloads round-trip unchanged.

## Classification

This batch is local-shape validation only:

- `brigade_desired_aor_cap` validates as a formation-keyed non-negative integer record.
- `og_orders` validates as an array of local order rows with non-empty corps/donor/focus ids, valid brigade posture, and positive `max_duration`.
- `settlement_holdouts` validates as a settlement-keyed local holdout record with boolean/string/non-negative numeric fields.
- `faction_officer_maturity` validates as a faction-keyed finite non-negative number record.

The validator deliberately does not resolve formation ids, corps ids, settlement ids, faction catalog membership for non-canonical historical strings, path reachability, OG feasibility, holdout ownership, officer availability, or materialize absent fields.

## Boundaries

No simulation behavior, scenario data, save schema version, migration, fixture refresh, baseline manifest, generated artifact, UI code, randomness, timestamps, or persisted output ordering changed.

Shared `validateNonNegativeIntegerRecord(...)` now emits diagnostics in `strictCompare` key order. Existing malformed-record expectations were updated to the stable order.
