## Deliverables

### Phase 1: Colorblind Modes (~1 session)
**Assigned to:** UI/UX Developer

- [ ] **Task 1.1:** Create color palette alternatives
  - Create: `src/ui/map/utils/colorblind_palettes.ts`
  - 3 modes: deuteranopia, protanopia, tritanopia (plus default)
  - Each mode defines: faction colors (RBiH/RS/HRHB), ethnicity colors, map gradient stops, severity colors (info/warning/critical)
  - Use: established colorblind-safe palettes (Okabe-Ito, ColorBrewer)

- [ ] **Task 1.2:** Wire palette into all color consumers
  - Create: `useColorPalette()` hook — returns current palette from settings
  - Modify: all GeoJSON builders (political, ethnic, supply, casualties, morale, operations, defense) — use palette colors not hardcoded hex
  - Modify: faction color references in ~15 components (OOBSidebar, FormationDetail, WarSummaryModal, territory bars, etc.)
  - Modify: MapModeLegend — colors match active palette

- [ ] **Task 1.3:** Add pattern overlay option
  - For colorblind players who still struggle with similar colors: add optional pattern fills (hatching, dots, stripes) to distinguish factions on the map
  - MapLibre fill-pattern property with SVG pattern sprites
  - Toggle in Settings: "Use pattern fills" (off by default)

- [ ] **Task 1.4:** Settings integration
  - Modify: SettingsScreen (register via section registry from v0.5.1)
  - Display section: add "Color Mode" dropdown (Default, Deuteranopia, Protanopia, Tritanopia)
  - Add: "Pattern fills" toggle
  - Preview: show faction color swatches that update live when mode changes

**Gate:** All 3 colorblind modes work. Map and UI colors adapt. Pattern fills available.

> /simplify → commit "feat(a11y): colorblind modes with 3 palettes + pattern fills"

### Phase 2: Keyboard Navigation (~1.5 sessions)
**Assigned to:** UI/UX Developer

- [ ] **Task 2.1:** Audit all interactive elements for keyboard access
  - Scan: all 55 map components for button/link/toggle elements
  - Verify: every interactive element is focusable (has tabIndex or is native button/input)
  - Fix: any `<div onClick>` → `<button>` (BrigadeRow already fixed in v0.3.1, check others)
  - Add: visible focus indicators (gold outline matching game aesthetic, not default blue)

- [ ] **Task 2.2:** Tab order for panel system
  - Define: logical tab order through panel rail (toolbar → sidebar → primary panel → secondary panel → map)
  - Implement: focus trap within modals (PeacePlan, Dayton, Event, Tutorial overlay)
  - Skip: map canvas from tab order (map has its own keyboard controls)

- [ ] **Task 2.3:** Keyboard shortcuts for all actions
  - Review: `useKeyboardShortcuts.ts` — ensure all major actions have shortcuts
  - Add missing shortcuts:
    - Panel navigation: Tab/Shift+Tab through panels
    - Corps selection: arrow keys in OOB sidebar
    - Operation management: Enter to confirm, Escape to cancel
    - Turn advance: Space bar (when no modal open)
    - Quick save: Ctrl+S (verify working)
    - Quick load: Ctrl+L
  - All shortcuts documented in Settings and Codex "Controls" entry

- [ ] **Task 2.4:** Map keyboard controls
  - Arrow keys: pan map
  - +/- or scroll: zoom
  - Home: reset to default view
  - Tab within map: cycle through formation icons (focus ring on selected)
  - Enter on focused formation: open FormationDetail

**Gate:** Full game playable without mouse. All actions have keyboard shortcuts.

> /simplify → commit "feat(a11y): keyboard navigation + focus indicators + shortcuts"

### Phase 3: Screen Reader Support (~1 session)
**Assigned to:** UI/UX Developer

- [ ] **Task 3.1:** ARIA labels on all interactive elements
  - Add: `aria-label` to all buttons, toggles, sliders
  - Add: `aria-describedby` for complex elements (e.g., formation cards link to their tooltip text)
  - Add: `role` attributes where semantic HTML isn't used

- [ ] **Task 3.2:** Turn summary as text
  - After turn advance: generate plain-text summary accessible to screen readers
  - Use: `aria-live="polite"` region that announces briefing items
  - Format: "[Turn 42] 3 battles fought. Decisive victory at Višegrad. Sarajevo siege continues. 2 events pending."

- [ ] **Task 3.3:** Map accessibility
  - Map canvas is inherently visual — full screen reader support is impractical
  - Provide: text alternative via "Situation Report" in command briefing (already sim-side from v0.5.1)
  - Provide: territory percentages as text in status bar (already in BottomStatusStrip)
  - Announce: map mode changes via aria-live

- [ ] **Task 3.4:** Panel announcements
  - When panel opens: screen reader announces panel title
  - When modal appears: screen reader announces modal purpose
  - Use: `aria-modal="true"` on all GlassPanel overlays

**Gate:** Screen reader users can follow game state, make decisions, and receive feedback.

> /simplify → commit "feat(a11y): ARIA labels + screen reader announcements"

### Phase 4: Rebindable Keys + Text Scaling (~0.5 session)
**Assigned to:** UI/UX Developer + Platform Specialist

- [ ] **Task 4.1:** Key rebinding system
  - Create: `src/ui/map/utils/keybinding_store.ts`
  - Store: key→action mapping in settings (JSON)
  - UI: "Controls" section in SettingsScreen — shows each action + its key, click to rebind
  - Support: single keys and modifier combos (Ctrl+S, Shift+Tab)
  - Validate: no duplicate bindings (warn if conflict)
  - Saved via settings_store.ts (v0.5.1)

- [ ] **Task 4.2:** Text scaling
  - Respect: system font size preferences (`window.devicePixelRatio`, CSS `rem` units)
  - Add: "Text Size" slider in Display settings (80%-150%)
  - Verify: all UI elements respond to text size changes without overflow/overlap
  - Tailwind: ensure all font sizes use `rem` not `px`

**Gate:** All keys rebindable. Text scales without breaking layout.
