## Design contract
- Visible palette affordance in campaign shell/map chrome plus Ctrl+K / Cmd+K where not conflicting. Existing editor/modal handling respected. Shortcut ignores composing/repeat/default-prevented events as appropriate and must not steal input or escape/Enter from another modal. Disabled behind required decisions, opening/transition/endgame and busy mutation surfaces. Fail closed when target becomes stale or unavailable.
- Accessible dialog with labelled search combobox/listbox, keyboard arrows/Home/End/Enter/Escape, visible focus, results count/no-results and focus restoration. No global shortcut firing while typing in the palette. Use existing modal stack ownership. Keyboard section links and optional existing shortcut help are discoverable; no bulk new destructive hotkeys/remapping scope.
- Small pure search-index/query module: player-safe projected inputs, own formations only, friendly names only; no raw ID fallback in visible/search text. Internal IDs may route known targets. Stable normalized case/diacritic matching and bounded results, deterministic tie ordering; no search dependency, network, telemetry or persistence of query/history. Entity selection invokes existing canonical owner handlers, including returning from Warroom to tactical inspection and normal map camera behavior.
- UI scale architecture follows an actual DOM/canvas trace before implementation. Prefer isolated UI surfaces and local preference controller; fixed-size text must actually grow. Do not zoom the document or map canvas. Keep pointer/MapLibre/Deck/minimap coordinates and campaign-scoped renderer lifetime unchanged. Shared Modal sizing/focus and viewport/max-height behavior must remain correct; header art/mappings are not owned. No silent viewport-dependent scale substitution. Every preset must be usable at every target viewport; overflow may scroll locally but essential close/search/actions cannot disappear.
- Proposed owned modules: new src/ui/map/command_palette/ and src/ui/map/preferences/ modules/components; minimal App.tsx/shell opener integration, SettingsScreen, globals.css and a narrowly scoped shared UI wrapper/Modal adjustment only if demonstrated necessary. EN/BCS message keys for new chrome using existing i18n; localization completeness remains outside this packet. No event modal/image/category map edits.
