## Context

This is a one-shot content generation milestone. 500-word historical essays are generated at development time using Sonnet, reviewed for accuracy, and shipped with the game binary. They unlock after the player experiences the corresponding event — creating a "learn by playing" educational loop.

**This is not runtime AI.** Essays are generated once, edited, and baked into the game. No API calls at runtime. No API key required.

**Cost:** ~100 essays × 500 words × Sonnet → ~$5-10 total generation cost.

**Educational value differentiator:** No other wargame ships with CIA-source-backed historical essays that unlock through gameplay.

## Deliverables

### Phase 1: Essay Generation Pipeline (~1 session)
**Assigned to:** Systems Programmer + Historian

- [ ] **Task 1.1:** Create essay generation script
  - Create: `tools/generate_essays.ts`
  - Reads: event definitions from `data/scenarios/events/war_*.json`
  - For each event with `essay: true` flag:
    - Builds prompt with: event title, event description, BB chapter reference, year/context
    - System prompt: "You are a military historian writing for an educational wargame about the Bosnian War. Write a 500-word essay explaining the historical context and significance of this event. Cite Balkan Battlegrounds (CIA, 2002) where possible. Tone: academic but accessible. No game mechanics — pure history."
    - Model: Sonnet
    - Output: markdown text
  - Writes: `data/essays/<event_id>.md` per essay
  - Tracks: `data/essays/manifest.json` with generation date, word count, review status

- [ ] **Task 1.2:** Generate essays for all flagged events
  - Flag ~60-80 events for essays (not all 100+ need one — skip trivial/ambient events)
  - Run generation script
  - Output: 60-80 markdown files in `data/essays/`
  - Expected: ~30,000-40,000 words total

- [ ] **Task 1.3:** Review and edit generated essays
  - Read each essay against BB source material
  - Fix: factual errors, dates, troop numbers, geographic accuracy
  - Fix: tone issues (too academic, too casual, insensitive language)
  - Flag: any essay that needs historian deep-dive (mark `review: 'needs_expert'` in manifest)
  - This step is partially manual — night shift does first pass, day shift reviews flags

**Gate:** 60-80 essays generated, first-pass reviewed, stored as markdown files.

## Architectural Decisions (FLAGGED FOR USER REVIEW)

1. **Essays are static files, not runtime AI.** Generated once with Sonnet, reviewed, shipped. No API key needed at runtime. This ensures: (a) quality control (reviewed by humans), (b) no cost per player, (c) works offline.

2. **Markdown format.** Essays stored as `.md` files, rendered in UI with basic markdown → HTML. No rich media (no images, no audio). Just text + citations.

3. **Unlock through gameplay, viewable forever.** Once an essay unlocks, it stays unlocked in that save file. The codex shows all essays (locked ones by title only — no spoilers). This creates a "collect them all" educational incentive.

4. **BB citations are crucial.** Every essay that references a specific claim should cite the BB volume and page. This is our credibility differentiator — a game that cites its sources.

5. **Night shift generates, day shift reviews.** Essay generation is autonomous. Fact-checking and sensitivity review require human judgment. Plan Phase 1 Tasks 1.1-1.2 are night shift, Task 1.3 is day shift. Phase 3 is entirely day shift.
