## Context

The game runs a complex simulation: sector building, BFS pathfinding, combat resolution, event evaluation, AI decisions, and diplomatic calculations — all per turn. The map renders 744 OSID polygons with dynamic overlays. Performance has never been systematically profiled — it "works" but may degrade on mid-range hardware or during 208-turn full campaigns.

**Targets:**
- Turn computation: <100ms on mid-range hardware (Intel i5-12400, 16GB RAM)
- Map render: 60fps during pan/zoom, <500ms for full redraw on mode change
- Startup: app launches in <3 seconds, map loads in <2 seconds
- Memory: no leaks across 208-turn games, <500MB peak usage

### Phase 2: Simulation Optimization (~1.5 sessions)
**Assigned to:** Systems Programmer + Performance Engineer

- [ ] **Task 2.1:** Optimize sector building
  - `buildEdgeAdjacency`: cache edge adjacency between turns (only recompute when territory changes)
  - `splitNonContiguousSectors`: use incremental split (only re-split sectors whose territory changed)
  - `classifyBrigadesByTerritory`: cache BFS results for unchanged territory
  - Target: sector building <20ms (from estimated 40-60ms)

- [ ] **Task 2.2:** Optimize BFS pathfinding
  - `findEmergencyRetreatOsid`, `evaluateReturnToCorps`, `mapOsidsToCorps` Phase 2 BFS
  - Cache: BFS distance maps per faction per turn (recompute only on territory change)
  - Pre-compute: friendly connectivity graph once per turn, share across all BFS consumers
  - Target: all BFS operations combined <15ms

- [ ] **Task 2.3:** Optimize combat resolution
  - `computeDefenderPower`, `computeAttackerPower`: pre-compute per-brigade combat power once per turn (not per-evaluation)
  - `predictAllAdjacentTargets`: cache adjacent target list per brigade (invalidate on territory change)
  - Target: combat phase <30ms

- [ ] **Task 2.4:** Lazy evaluation for non-critical systems
  - Negotiation capital: compute every 4 turns, not every turn (capital changes slowly)
  - Campaign statistics: compute on demand, not per turn
  - Briefing assembly: only compute sections with changes (skip "No significant activity" computation)

- [ ] **Task 2.5:** Re-run benchmark, verify improvements
  - Run `tools/perf_benchmark.ts` with optimizations applied
  - Target: overall turn time <100ms (p95)
  - If still over: profile again, find next hot path

**Gate:** Turn computation <100ms p95. No behavioral changes (determinism preserved).

### Phase 3: Map Rendering Optimization (~1 session)
**Assigned to:** Graphics Programmer

- [ ] **Task 3.1:** GeoJSON layer caching
  - Cache: built GeoJSON for each map mode (invalidate only on territory change)
  - Currently: GeoJSON rebuilt on every render cycle
  - MapLibre: use `source.setData()` only when data actually changes

- [ ] **Task 3.2:** Tile loading priority
  - Configure: MapLibre to prioritize visible viewport tiles
  - Reduce: off-screen tile loading during rapid pan
  - Set: `maxTileCacheSize` appropriate for map complexity

- [ ] **Task 3.3:** Layer visibility optimization
  - Disable: non-active map mode layers (don't render 7 mode layers, only the active one)
  - Use: `setLayoutProperty(layer, 'visibility', 'none')` for inactive modes
  - Currently: unclear if all layers render simultaneously

- [ ] **Task 3.4:** Formation icon optimization
  - If >100 formation icons visible: use MapLibre symbol clustering or reduce icon detail
  - Pre-render: icon sprites as a single atlas (not individual SVGs)

**Gate:** 60fps pan/zoom. <500ms full map mode switch. No visual regressions.

### Phase 4: Memory & Startup (~0.5 session)
**Assigned to:** Platform Specialist

- [ ] **Task 4.1:** Memory leak audit
