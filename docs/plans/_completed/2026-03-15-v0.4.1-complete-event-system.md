# v0.4.1 — Complete Event System — Implementation Plan

**Date:** 2026-03-15
**Status:** PLAN — ready for execution
**Overseer:** Orchestrator
**Architect:** Makes decisions, flags for user review
**Prerequisites:** v0.3.1 ✓ (patron events, peace plan events), v0.4.0 (peace interactivity), Infrastructure (deterministic_random.ts, GlassPanel.tsx)

**Cross-Plan Integration (from CROSS_PLAN_REVIEW_V04.md):**
- This event system is the **universal event bus** — v0.4.3 economy events, v0.4.4 officer events, and v0.3.3 AoR breach events all post through this system. Design for extensibility.
- Event categories: `military | political | humanitarian | diplomatic | economic | command | territorial`
- Command Briefing: aggregate all events into a post-turn brief for the player.
- All UI panels use shared `GlassPanel.tsx` component.
- All random event triggers use shared `deterministicRandom()` utility.

---

## Situation

Three parallel event systems already exist:
- **B1 Event Registry** (`src/sim/events/`) — 15 events, narrative-only, no mechanical effects
- **Phase 0 Events** (`src/phase0/phase0_events.ts`) — 7 types, snapshot-based, complete
- **Patron Events** (`src/sim/negotiation/patron_events.ts`) — 4 scripted events with mechanical effects

The framework is 70% built. What's missing: mechanical effects on B1 events, player decision points, comprehensive event coverage (1993-1995), scenario-level event customization, and a unified event UI.

## Deliverables

### Phase 1: Unified Event Effect System (~1 session)
**Assigned to:** Systems Programmer

Extend the B1 event registry to support mechanical effects — not just narrative text.

- [ ] **Extend `EventEffect` type** in `event_types.ts` — add effect kinds:
  - `morale_change`: `{ factions: FactionId[], delta: number }`
  - `supply_delta`: `{ factions: FactionId[], delta: number }`
  - `cohesion_change`: `{ factions: FactionId[], delta: number }`
  - `humanitarian_impact`: `{ faction: FactionId, war_crimes_delta: number }`
  - `patron_pressure`: `{ faction: FactionId, override_delta: number, support_delta: number }`
  - `alliance_change`: `{ delta: number }` (RBiH-HRHB alliance)
  - `negotiation_capital`: `{ faction: FactionId, dimension: string, delta: number }`
  - `narrative`: `{ text: string }` (existing, keep as default)
- [ ] **Create `applyEventEffects(state, effects[])`** in `src/sim/events/apply_effects.ts` — deterministic state mutation from event effects. Sorted by effect kind for reproducibility.
- [ ] **Extend `evaluateEvents()`** to call `applyEventEffects()` after firing each event
- [ ] **State tracking** — add `fired_event_ids: string[]` to GameState to prevent re-fire across save/load (patron_events already does this pattern)
- [ ] **Tests** — effect application for each effect kind, no-refire guard, determinism

**Gate:** Events can modify game state. Run 40w scenario, verify morale/supply/etc change when events fire.

→ /simplify → commit

### Phase 2: Player Decision Events (~1 session)
**Assigned to:** Gameplay Programmer + UI/UX Developer

Add events that present the player with choices and apply different consequences based on response.

- [ ] **Extend `EventDefinition`** with decision fields:
  ```typescript
  response_options?: Array<{
      id: string;
      label: string;            // "Accept ceasefire" / "Reject ceasefire"
      description: string;      // consequence preview
      effects: EventEffect[];   // what happens if chosen
  }>;
  requires_player_response?: boolean;  // true = pause for player, false = auto-resolve
  bot_response_logic?: 'accept_first' | 'reject_all' | 'capital_weighted';
  ```
- [ ] **Pending decision state** — add `pending_event_decision` to GameState (like `pending_peace_plan`). Blocks turn advance until player responds.
- [ ] **Bot auto-response** — non-player factions auto-pick based on `bot_response_logic` and capital position
- [ ] **Decision Event UI** — `EventDecisionModal.tsx` following canonical visual style:
  - Glassmorphism floating panel over map
  - Event narrative text, faction context
  - 2-3 response buttons with consequence preview
  - Accent-gold selected option, phosphor-green for positive consequences, red for negative
- [ ] **IPC** — `respond-to-event` handler in `electron-main.cjs`
- [ ] **Tests** — decision presented, player responds, effects applied, bot auto-responds

**Gate:** Player sees decision event, chooses response, game state changes accordingly.

→ /simplify → commit

## Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|-----------|
| Effect system breaks calibration | Medium | Effects are small deltas (±5-15), not game-changing. Run 40w comparison before/after. |
| Too many events per turn overwhelms player | Low | Queue system shows one at a time. Non-decision events can auto-acknowledge after delay. |
| Historical event timing clashes with existing patron events | Medium | Patron events and B1 events are separate systems. Verify no double-fire for same historical moment. |
| Event JSON schema too rigid for future content | Low | Design schema with optional fields. Validate with JSON schema test. |

## Visual Style

All event UI follows the canonical ops-planning visual language:
- Dark NATO ops center aesthetic
- Glassmorphism (`backdrop-blur`) on event modal
- Accent-gold headlines, phosphor-green for positive effects, red for negative
- Event type badge (Military / Political / Humanitarian / Diplomatic)
- Decision buttons: gold border for recommended, neutral for alternative
- Map highlight behind modal for geographically-relevant events

## Visual Assets (User-Generated via Gemini Pro)

Assets are generated externally by the user. Implementation uses **placeholders** until assets are delivered.

| Asset Set | Count | Dimensions | Placeholder Strategy |
|-----------|-------|-----------|---------------------|
| Event illustrations (1992) | 15-20 | 800×450 WebP | Event type color gradient (Military=olive, Political=blue, Humanitarian=amber, Diplomatic=grey) with event headline overlaid |
| Event illustrations (1993-1995) | 20-30 | 800×450 WebP | Same gradient placeholders |
| Peace plan maps | 5 | 600×400 WebP | Programmatic map: BiH outline with faction-colored partition overlay drawn from `proposed_split` data |

**Event JSON schema includes optional image field:**
```json
{
  "id": "jna_withdrawal",
  "image": "events/event_jna_withdrawal.webp",
  ...
}
```
When `image` is missing or file doesn't exist, `EventModal.tsx` renders the type-colored gradient placeholder. No crashes on missing assets.

**Peace plan maps** can be programmatically generated from the `proposed_split` percentages as a simple choropleth — this serves as both placeholder AND a functional alternative if artistic maps aren't delivered.
