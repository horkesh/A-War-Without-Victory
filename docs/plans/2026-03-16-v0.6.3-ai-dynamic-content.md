## Context

The game has 100+ scripted events and formula-based bot negotiations. This milestone adds two AI-powered content systems:

1. **Procedural events** — AI generates events reacting to what *actually happened*, not just scripted history. If Srebrenica falls early, the international response is different. If the player avoids ethnic cleansing, the IVP curve shifts.

2. **Peace negotiation dialogue** — Multi-turn conversation with AI-Milošević/Izetbegović/Tuđman at the Dayton table. The AI pushes back based on capital position. Must reach game-mechanical outcomes (DaytonResult), not open-ended chat.

**Cost model:**
- Procedural events: Haiku, ~$0.01/turn × 188 turns = ~$1.88/game
- Peace dialogue: Sonnet, ~$0.05-0.20/negotiation × 5-6 peace plans = ~$0.30-1.20/game
- Total: ~$2-3/game at full engagement

All features require API key. Cadet Mode (no API) uses scripted events and formula Dayton (unchanged).

## Deliverables

### Phase 1: Procedural Event Generator (~2 sessions)
**Assigned to:** Gameplay Programmer + Systems Programmer

- [ ] **Task 1.1:** Create event generation module
  - Create: `src/sim/ai_commander/event_generator.ts`
  - Function: `generateProceduralEvent(state: GameState, turn: number): Promise<ProceduralEvent | null>`
  - Prompt structure:
    - System: "You are the event narrator for a Bosnian War simulation. Generate a historically plausible event based on the current situation."
    - Context: current territory by faction (%), active sieges, recent battles (last 3 turns), casualty totals, alliance state, IVP level, active operations, recent events (last 5)
    - Constraints:
      - Return JSON matching EventDefinition schema (title, description, category, effects)
      - Effects limited to existing effect types (morale, supply, cohesion, patron, humanitarian, alliance, negotiation_capital)
      - Effect magnitudes bounded: morale ±5, supply ±10, cohesion ±3, patron ±5
      - Must be historically plausible for the Bosnian War context
      - No fantasy/fictional content — everything that could have happened, given the game state
      - 50-150 words description
    - Output: structured JSON
  - Model: Haiku (~$0.01/event)
  - Rate limit: max 1 procedural event per turn, 50% chance of firing (deterministicRandom)

- [ ] **Task 1.2:** Guardrails and validation
  - Create: `src/sim/ai_commander/event_guardrails.ts`
  - Validate AI output:
    - Schema validation (all required fields present, types correct)
    - Effect magnitude bounds (reject events with morale ±20 — AI hallucination guard)
    - Content filter: no modern references, no other conflicts, must mention BiH/Bosnia/relevant geography
    - Deduplication: reject if title/description >80% similar to any event in last 10 turns
  - On validation failure: discard event, log to decision_log, no retry
  - Expected ~10-20% rejection rate (acceptable)

- [ ] **Task 1.3:** Wire into event pipeline
  - Modify: `src/sim/events/evaluate_events.ts`
  - After scripted event evaluation: if AI mode ≥ Observer AND no scripted event this turn AND 50% probability:
    - Call `generateProceduralEvent()`
    - If valid: merge into event queue
    - Tag: `source: 'ai_generated'` (distinguishable from scripted events in UI)
  - Procedural events shown with subtle "AI" indicator in EventLogPanel

- [ ] **Task 1.4:** Reactive event prompts
  - Create context-aware prompt templates:
    - **Siege event**: when a city has been besieged >10 turns, prompt focuses on siege conditions
    - **Offensive event**: when a major operation is active, prompt focuses on combat/logistics
    - **Diplomatic event**: when IVP crosses thresholds, prompt focuses on international response
    - **Humanitarian event**: when displacement >5000 this turn, prompt focuses on civilian impact
    - **Alliance event**: when alliance value changes >0.1, prompt focuses on faction relations
  - Template selection: based on current game state analysis (most dramatic dimension)

- [ ] **Task 1.5:** Tests
  - Create: `tests/event_generator.test.ts`
  - Test: prompt construction includes correct state summary
  - Test: guardrails reject out-of-bounds effects
  - Test: deduplication catches similar events
  - Test: no API key → generator returns null (no error)
  - Test: validation failure → graceful discard

**Gate:** AI generates historically plausible events reactive to game state. Guardrails prevent hallucinated mechanics.

### Phase 2: Peace Negotiation Dialogue (~2 sessions)
**Assigned to:** Gameplay Programmer + UI/UX Developer

  - Flow per peace plan or Dayton:
    1. Player makes initial proposal (territory + institutions from v0.5.0 UI)
    2. AI responds as each bot faction leader:
       - RS: Milošević (or Karadžić, depending on patron override level)
       - RBiH: Izetbegović
       - HRHB: Tuđman (or Boban pre-Washington)
    3. Response includes: accept/reject/counter-proposal + in-character dialogue
    4. Player can adjust and resubmit (up to 3 rounds)
    5. Final round: AI applies patron pressure logic → forced convergence

- [ ] **Task 2.2:** Leader personality prompts
  - Create: `src/sim/ai_commander/leader_profiles.ts`

  - **Karadžić**: Maximalist, ideological, stubborn. Rejects any plan that doesn't preserve Greater Serbia. Loses influence to Milošević over time. "Republika Srpska is not negotiable."
  - **Izetbegović**: Principled, stubborn on sovereignty, willing to compromise on details. Values international legitimacy. "A unified Bosnia or nothing — but the details can be discussed."
  - **Tuđman**: Strategic, values Croatian state interests over Bosnian Croats. Will sacrifice HRHB if it serves Zagreb. "Croatia's interests in Bosnia are secondary to Croatia's future in Europe."

  - Round indicator: "Round 1 of 3" / "FINAL ROUND — patron pressure applied"

- [ ] **Task 2.4:** Mechanical outcome convergence

  - Apply: patron override force-acceptance for items within override threshold
  - Result: `DaytonResult` (same as formula path — dialogue changes the experience, not the mechanical framework)
  - Fallback: if AI fails to produce parseable positions, use formula bot result

- [ ] **Task 2.5:** Tests

  - Test: 3-round limit enforced
  - Test: patron override correctly narrows options in final round
  - Test: parse failure → formula fallback (no broken game state)

## Architectural Decisions (FLAGGED FOR USER REVIEW)

1. **Procedural events use existing effect types only.** AI cannot invent new game mechanics. This prevents hallucinated systems from breaking the game.

2. **Effect magnitudes are hard-bounded.** Morale ±5, supply ±10. Even if AI returns morale: +50, guardrails clamp it. This prevents cascade regressions from rogue AI output.

3. **Dialogue converges to formula outcome.** The AI dialogue changes the EXPERIENCE (immersion, drama) but not the MECHANICAL framework. DaytonResult is computed by the same formula bot path whether dialogue is on or off. This ensures game balance is independent of AI quality.

4. **Milošević vs Karadžić**: When patron override ≥75, Milošević speaks at the table (not Karadžić). This mirrors history — Karadžić wasn't at Dayton. The AI selects the speaker based on patron override level.
