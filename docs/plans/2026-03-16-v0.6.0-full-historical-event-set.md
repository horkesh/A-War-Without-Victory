## Context

The event system infrastructure is production-ready. What's missing is **content depth**: only 39 events cover 208 turns of war. Key historical moments are absent (Tuzla shelling, Goražde siege phases, Srebrenica column breakout, Abdić revolt). Only 6 events offer player decisions. No events use the `probability` field. No event chains exist (one event triggering another).

**Target:** 100-120 events total. 20-25 decision events. 10+ probabilistic events. Event chain support for cascading consequences.

**Content authority:** Balkan Battlegrounds (BB1/BB2), extracted knowledge base at `data/derived/knowledge_base/`, `docs/10_canon/HISTORICAL_TIMELINE_MASTER.md`.

### Phase 1: Event System Enhancements (~1 session)
**Assigned to:** Systems Programmer

- [ ] **Task 1.1:** Add event chain support
  - Modify: `src/sim/events/event_types.ts`
  - Add: `triggers_event?: { event_id: string, delay_turns: number, condition?: string }` to EventDefinition
  - When an event fires and has `triggers_event`, schedule the follow-up event
  - Modify: `src/sim/events/evaluate_events.ts` — check scheduled chain events alongside time-triggered ones
  - Example chain: `srebrenica_encirclement` (w12) → `srebrenica_shelling` (w14) → `srebrenica_safe_area_declared` (w16)

- [ ] **Task 1.2:** Add faction-specific event visibility
  - Modify: `src/sim/events/event_types.ts`
  - Add: `visible_to?: FactionId[]` — if set, only these factions see the event. Others get fog-of-war version or nothing.
  - Add: `fog_description?: string` — abbreviated text shown to factions not in `visible_to`
  - Example: Concentration camp discovery — RS knows but gets "international attention increases"; RBiH/HRHB get full description

- [ ] **Task 1.3:** Add conditional event triggers beyond week number
  - Modify: `src/sim/events/evaluate_events.ts`
  - Support trigger conditions:
    - `territory_below: { faction, threshold }` — fires when faction territory drops below %
    - `enclave_fallen: { enclave_id }` — fires when specific enclave lost
    - `alliance_below: { threshold }` — fires when RBiH-HRHB alliance value drops below
    - `casualties_above: { faction, threshold }` — fires when cumulative KIA exceeds
    - `ivp_above: { threshold }` — fires when IVP crosses level
  - These are checked each turn alongside week-based triggers

- [ ] **Task 1.4:** Enable probabilistic events
  - Modify: `src/sim/events/evaluate_events.ts`
  - If event has `probability: number` (0-1), use `deterministicRandom(turn_seed, event_id)` to decide if it fires
  - Events with probability fire at most once (track in `state.events.fired_event_ids`)

- [ ] **Task 1.5:** Per-faction decision response options
  - **Known bug (found 2026-03-16 nightshift audit):** All 6 existing decision events hardcode `"faction": "RBiH"` in response effects. If player is RS or HRHB, their accept/reject choice affects RBiH stats, not their own.
  - Fix: Add per-faction response variant support. Each decision event needs faction-specific effects, or use `"faction": "self"` sentinel resolved to the responding faction at application time.
  - Modify: `src/sim/events/evaluate_events.ts` — resolve `"self"` faction in response effects before applying
  - Modify: `src/sim/events/resolve_decision.ts` — same resolution for player decisions
  - Modify: All 6 existing decision event JSON entries — either add per-faction variants or use `"self"` sentinel
  - All new decision events in Phases 2-4 must use the per-faction pattern from the start

- [ ] **Task 1.6:** Tests for new event features
  - Create: `tests/event_chains.test.ts`
  - Test: chain scheduling, conditional triggers, probability gating, faction visibility
  - Test: per-faction response resolution (`"self"` → responding faction)

**Gate:** Event system supports chains, conditions, probability, faction visibility, and per-faction decision responses.

## Architectural Decisions (FLAGGED FOR USER REVIEW)

1. **Event count target: 100-120** (from 39). This is ~60-80 new events. Substantial content authoring. Most events are narrative + 1-2 effects — not complex code.

2. **Chain events are deterministic**: Chain scheduling stored in GameState. Save/load preserves pending chains. No non-determinism introduced.

3. **Probabilistic events use deterministicRandom**: Same seed + same turn = same outcome. Replay-safe.

4. **Image placeholders**: Events have an `image` field. All new events get `image: null` (gradient placeholder from v0.4.1). Real images from the Gemini Pro visual asset pipeline (external).
