Data New Lesson A
proposed_split constants are historical claims AND mechanical routing parameters — historian gate required before commit
Before any proposed_split is committed to peace_plan_data.ts, dispatch /historian: "What territorial allocation did plan X assign to faction Y?"
Why it matters: The split value directly determines whether a faction routes to hard-reject or personality scoring via the floor-gap calculation. A wrong constant changes faction behavior, not just display.
Evidence
O-S RS:30→52 flipped routing from auto-reject to scoring (gap 35pp→13pp). VOPP RS:30→43 changed floor calibration baseline.
Do instead
Add // Source: [citation] above each proposed_split entry. Absence of comment = unverified constant.
Target file
docs/life_lessons/data_pipeline.md
Architecture New Lesson B
A single floor threshold across structurally different peace plans silently fails for plans with different rejection bases
When adding a new peace plan, compute its sim gap in OSID-count units and add it to RS_PLAN_FLOOR_GAPS explicitly.
Why it matters: VOPP/O-S rejections are Assembly votes; CG rejection is a 96% referendum. These require different floors. A single constant can't represent qualitatively different political events.
Evidence
CG gap ≈14pp (OSID-count) < 18pp single floor → silently routed to scoring for 3 phases. 96% referendum ignored by engine.
Do instead
const sim_gap = RS_osid_pct − proposed_RS_pct. Add entry to RS_PLAN_FLOOR_GAPS for every new plan.
Target file
docs/life_lessons/architecture.md
Architecture New Lesson C
Political engine changes gated on specific trigger_weeks are calibration-safe by construction
If all trigger_week values exceed scenario duration, state "calibration-inert by construction" — no 40w run needed to validate political changes.
Why it matters: Phases 5+6 heavily modified computePoliticalPeacePlanResponse. Calibration showed 0.0pp delta. Root cause: peace_plans.ts:139 gates on trigger_week === warWeek. Political engine is structurally inert to 40w runs when all trigger weeks are post-w40.
Evidence
n1344 = n1343 = 93.3%. O-S triggers w72, CG triggers w78+, Holbrooke triggers w176–183. All beyond w40 scenario.
Do instead
Document trigger weeks in every phase report. The temporal inertness is a correctness property, not a gap.
Target file
docs/life_lessons/architecture.md
Data New Lesson D
Sim territory is OSID-count; historical sources are area-weighted — design floor thresholds in sim units
Always convert: sim_gap = RS_osid_count_pct − proposed_RS_pct. State which basis you're using in all floor calculations.
Why it matters: Game Designer recommended VOPP floor = 27pp from area-weighted historical data (RS≈70% − 43% = 27pp). Sim OSID-count gives RS≈65%, gap = 22pp. A 27pp floor would never trigger (22 < 27), silently breaking VOPP hard-reject.
Evidence
Area-weighted RS ≈70% (historical records). OSID-count RS ≈65% (712 OSIDs). 5pp denominator gap sufficient to invert threshold direction.
Do instead
Write: "RS current OSID-count = X%. Plan proposes Y%. Sim gap = X−Y = Zpp. Floor = N where N < Z." Never design from area-weighted alone.
Target file
docs/life_lessons/data_pipeline.md
