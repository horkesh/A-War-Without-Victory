Proposed New Lessons

PROPOSED   [Architecture] Shared mutable arrays: verify append vs replace semantics

Context: generateAllCorpsOrders() assigned state.military.army_hq_overrides = armyOverrides, replacing any sync overrides the gathering had pushed earlier in the pipeline. Silent data loss — no error, no warning.

Wrong approach: Writing to a shared state array with assignment (=) when multiple pipeline steps contribute to it.

Right approach: When multiple pipeline steps write to the same state array, use append/merge (push or spread) not assignment. If a step MUST reset the array, it should run FIRST, not after other contributors.

How to apply: When adding a new pipeline step that writes to an existing state field, grep for ALL other writers. Check: does any writer use = (replace) after your step runs? If so, fix the ordering or change to merge.

PROPOSED   [History] Verify historical dates against primary sources, never from memory

Context: 28 of 41 historical events had incorrect turn numbers. Some were 25 weeks off (anti-sniping agreement). The East Mostar siege was placed 10 months before the HVO-ARBiH war. Ceasefire and Dayton talks were in reversed chronological order. All errors were plausible enough to pass casual review.

Wrong approach: Setting event dates from general knowledge ("Mostar siege was 1992, right?"). Memory conflates the JNA siege (1992) with the HVO siege (1993).

Right approach: Every historical date must be verified against a primary source (ICTY records, UNSCR documents, Balkan Battlegrounds). Compute turn numbers from the formula: turn = (date - April 6, 1992) / 7. Cross-check causal ordering (event B cannot fire before event A if B depends on A).

How to apply: When adding or modifying historical events, cite the source and date. Add a requires_events field for causal dependencies. The timeline integrity tests (event_timeline_integrity.test.ts) enforce ordering automatically.
