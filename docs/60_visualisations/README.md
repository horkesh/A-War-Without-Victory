# docs/60_visualisations

Canonical location for AWWV visualization artifacts: Graphviz DOT sources,
HTML viewers, mockups, and standup/report renders.

This README documents the static event-family graph DOT exports shipped in
Phase F Packet 4 and explains how to render them to SVG without a local
Graphviz install. See the top-level `CLAUDE.md` "Visualization Output"
section for the canonical-location rule.

## Rendering DOT to SVG

Graphviz `dot` is not assumed to be installed locally on AWWV development
machines. Three options:

### Option A — Online viewer (no install)

Paste the `.gv` file contents into one of the following:

- https://dreampuf.github.io/GraphvizOnline/
- https://edotor.net/
- http://magjac.com/graphviz-visual-editor/

Select layout `dot` and engine output `svg`. Save the SVG via the viewer's
download/export action.

This is the recommended path for one-off review of a single subtree.

### Option B — Local Graphviz install

Install Graphviz:

- Windows (Chocolatey): `choco install graphviz`
- Windows (Scoop): `scoop install graphviz`
- macOS: `brew install graphviz`
- Debian / Ubuntu: `sudo apt install graphviz`

Then render any `.gv` file to SVG (or PNG / PDF):

```bash
dot -Tsvg docs/60_visualisations/event_family_full_graph.gv \
    -o docs/60_visualisations/event_family_full_graph.svg

dot -Tpdf docs/60_visualisations/event_family_full_graph.gv \
    -o docs/60_visualisations/event_family_full_graph.pdf
```

The full graph is large (274 nodes); rendering as PDF often produces a
more legible result than SVG at default zoom. For SVG, open in a browser
and zoom freely.

### Option C — VS Code preview

Install the **Graphviz Interactive Preview** extension
(`tintinweb.graphviz-interactive-preview`) or **Graphviz Preview**
(`EFanZh.graphviz-preview`). Open any `.gv` file and use the preview
command. Useful for quick iteration while editing the event catalog.

## Regenerating the DOT files

The DOT files are produced by `tools/diagnostics/event_family_graph.ts`
(Phase F Packet 3). Re-run after any change to the event catalog
(`data/scenarios/events/war_199*.json` or `consequences.json`).

Use `node node_modules/tsx/dist/cli.mjs` (NOT `npx tsx`) per project
convention in `CLAUDE.md`.

```bash
# Full catalog graph
node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format dot \
    --out docs/60_visualisations/event_family_full_graph.gv

# RS subtree (foundational: rs_strategic_goals)
node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format dot --root rs_strategic_goals \
    --out docs/60_visualisations/event_family_rs_subtree.gv

# RBiH subtree (foundational: rbih_state_identity)
node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format dot --root rbih_state_identity \
    --out docs/60_visualisations/event_family_rbih_subtree.gv

# HRHB subtree (foundational: hrhb_political_goal)
node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format dot --root hrhb_political_goal \
    --out docs/60_visualisations/event_family_hrhb_subtree.gv

# Ring 3 single-family slices
node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format dot --family hrhb_camp_exposure \
    --out docs/60_visualisations/event_family_ring3_hrhb_camps.gv

node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format dot --family rs_camp_exposure_response \
    --out docs/60_visualisations/event_family_ring3_rs_camps.gv
```

Identify the current foundational event ids at any time with:

```bash
node node_modules/tsx/dist/cli.mjs tools/diagnostics/event_family_graph.ts \
    --format tree --depth 0
```

The tool is deterministic (sorted iteration via `strictCompare`, no
`Math.random` / `Date.now` / timestamps), so re-runs against an unchanged
catalog produce byte-identical output.

## Legend

The F3 DOT renderer emits a `cluster_legend` subgraph in every file
showing the family colors and the Ring 3 border style. Reference:

### Node fill (family group)

| Color | Family group | Examples |
|---|---|---|
| `lightcoral` | RS (Republika Srpska) | `rs_strategic_goals`, `rs_drina_campaign`, `rs_camp_exposure_response` |
| `lightblue` | RBiH (ARBiH) | `rbih_state_identity`, `rbih_arms_embargo_lift_advocacy_1993` |
| `lightgreen` | HRHB (HVO) | `hrhb_political_goal`, `hrhb_camp_exposure` |
| `lightyellow` | Cross-faction | `x_*`, `h5_*`/`h6_*`/`h7_*`/`h8_*`, `un_*` |
| `white` | Other / no family | Foundational helpers, scenario meta-events |

### Node border (Ring 3 marker)

| Style | Meaning |
|---|---|
| `color=red, penwidth=2` | Ring 3 sensitive history — exact-match against `RING3_SENSITIVE_FAMILIES` or prefix-match against `RING3_SENSITIVE_PREFIXES` in `src/sim/events/event_families.ts` (e.g., `rs_drina_campaign`, `hrhb_camp_exposure`, `un_safe_area_*`, `un_hostage_*`). |
| default | Non-sensitive event. |

### Edge color / style (relation kind)

| Color | Style | Relation | Source field |
|---|---|---|---|
| `blue` | solid | `enables` | `response_options[].enables_events_runtime[]` |
| `red` | solid | `closes` | `response_options[].closes_events_runtime[]` |
| `gray` | dashed | `future_consequence` | `response_options[].future_consequences[].opens_events[]` |

Each edge carries a `label` matching the relation name for legibility in
SVG renders.
